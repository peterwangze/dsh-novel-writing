### F-5（P3·讨论）隔离挂载脚本「路径 ①/② 双报文」的记录名把双证绑到**成功路径**，而成功路径无报文
- **位置**：`scripts/isolated-preset-mount.mjs` L186-221（`tryMount`）、L230-231 与 L248-249（记录项名声称「路径 ① 报文 `error.message` / 路径 ② toast 原文 `error.details.reason`」）、L255（`report.mutation`）。
- **事实依据**（实测报告逐字，**机制本身无缺陷**）：`tryMount` 的 catch 正确读取了 `error.details.reason`（L217）。红态 mutation 两字段均有值——`message = "agent-presets: preset \"novel-writing\" failed to mount: failed to apply loader entry persona (@deepseek-ai/dsh-persona): invalid config:\n  - $.prefix missing required value (at prefix) (…\n v-bug007-31UtXF\dsh-home\.agent-presets\novel-writing\agent.cordis.yml)"`，`reason = "failed to apply loader entry persona (@deepseek-ai/dsh-persona): invalid config:\n  - $.prefix missing required value (at prefix) (…)"`；`report.mutation.red.{message,reason}` 与记录项 detail 均**已承载**两字段。缺口仅在**语义绑定**：① 记录项名（L230-231 / L248-249）把「双字段」与**成功/基线路径**并列，而成功路径实测 `mount.first = {"ok":true,"message":null,"reason":null}`（无报文可双证）；② 若无变异实验，路径 ② 的 `details.reason` 在**任何**路径都不会有值 ⇒ 「双证」实为**变异实验独有**的证据形态。
- **影响**：仅记录可读性/证据可追溯性——若后续有人只读记录项名，会以为成功路径也断言了路径 ② 字段（实际没有），或在重构中删除变异实验的 `reason` 采集而无人察觉该证据面消失。**不影响**本轮判定（红态双字段确已实测取得，用户两条消费路径的报文均被实证）。
- **修复建议**：把 L230-231 / L248-249 的记录名改为「成功即挂载通过（无报文）；报文双证见**变异实验** `report.mutation.red.{message,reason}`」，并在记录 detail 中标注「`details.reason` 仅在宿主返回 `RemoteError.details` 的失败路径有值」。

### F-6（P3·讨论）隔离环境未全量重定向 + 「零写入」复核范围窄于断言口径
- **位置**：`scripts/isolated-preset-mount.mjs` L64-75（`realEnvFingerprint`）、L134-144（仅设 `DSH_HOME`）、L263-266（记录名「真实 `$DSH_HOME` 只读复核…零写入」）。
- **事实依据**：与 REL-006 EVD-098（`$HOME` 只读变量冲突致误写真实 profile 根，RISK-006 打开中）同一失效家族：该事故的纠正措施是「`DSH_HOME`/`USERPROFILE`/`HOME`/`APPDATA`/`LOCALAPPDATA`/`XDG_*`/`pnpm`/`npm_config_*` 全量重定向 + 逐行真实路径泄漏检测器 + fail-closed 路径断言」。本脚本只有第一项与 containment 断言，**未**重定向 `USERPROFILE`/`HOME`/`APPDATA`/`LOCALAPPDATA`，也**未**做泄漏检测器；`realEnvFingerprint` 只覆盖 `.agent-presets/novel-writing/{.dsh-bundle-version, agent.cordis.yml}`，而记录名表述为整个真实 `$DSH_HOME`。

### F-7（P3·讨论）`shutdown` 未置于 `finally`；夹具求值作用域为自建对象 + `resolveConfig` 调用层级与加载器不同
- **位置**：`scripts/isolated-preset-mount.mjs` L154-273（`await booted.shutdown.shutdown(0)` 在 `try` 块末尾 L268，非 `finally`）；`test/fixtures/host-surfaces/preset-schema-face.mjs` L336（`const ctx = { baseUrl: pathToFileURL(composition).href, process, console }`）、L238（`oracle.interpolate(ctx, row.config)`）、L272（`oracle.resolveConfig({ Config: schema }, config)`）。
- **事实依据**：(a) 若 `try` 中任一 `await` 抛错（`import` 宿主模块失败、`loadRunProfile` 的 `die` 之外异常等），进程退出前不执行 `shutdown` ⇒ 隔离实例的 web 服务可能残留至进程终止（正常路径实测无残留：运行后无新增 node 进程、临时根已删、`%TEMP%\nv-bug007-*` 为空）。(b) 夹具求值作用域是**脚本自建对象**，而加载器实际用 `this.ctx`（`loader/lib/index.js` L161 `ctx.extend({ baseUrl: ctx.baseUrl })`，L380 `evaluate(expr){ return evaluate(this.ctx, expr) }`）——当前组合的 `!!js` 只用 `process` + `baseUrl`，故实测等价（24 行启用行零 `CONFIG_EXPR_ERROR`）；若未来组合引入依赖其它 ctx 键的表达式，夹具会误报 `CONFIG_EXPR_ERROR`（fail-closed 方向，非误绿）。(c) 夹具调用 `cordis.resolveConfig({ Config }, config)`，加载器实际走 `Service.prototype[Service.resolveConfig]`（`cordis-plugin-loader/lib/index.js` L727，服务级）；本次由**隔离实例实证**两者报错文本逐字一致（`invalid config: - $.prefix missing required value (at prefix)`）⇒ 层级差异当前无判别力影响，仅作留档。
- **影响**：低（(a) 仅失败路径影响资源回收；(b)/(c) 当前无判别力差异，且偏差方向均为 fail-closed）。
- **修复建议**：把 `await booted.shutdown.shutdown(0)` 移入 `finally`（用可选链保护 `booted`）；在夹具注释中标注「求值作用域与 `resolveConfig` 层级已由 `isolated-preset-mount` 变异实验对齐（附证据路径）」，避免后续把这层差异当作等价关系。

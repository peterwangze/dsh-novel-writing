事实依据：`client.js:2022-2024`。


| 边界 | 核验结果 |
|------|---------|
| Windows 盘符大小写 | ✅ `toLowerCase()` 覆盖（`D:\foo` ≡ `d:/foo`） |

| 尾分隔符 | ✅ `\/+$` 去除（多尾斜杠亦除）；根盘符 `D:\` → `d:` 两侧一致 |

## 3. 发现列表

### P2-1（建议修改，非阻塞）分组头键盘不可达 — 偏离代码库自身惯例

- **位置**：`lib/client.js:2090`
- **事实**：分组头为 `el('div', { role: 'button', 'aria-expanded': ... , onClick })`——有 ARIA 角色与状态，但**无 `tabIndex`/`onKeyDown`**，键盘用户无法聚焦或切换折叠。而代码库对可点击行的既有惯例是**原生 button**（FileTree `row()` = `el('button', ...)`，client.js:1688），原生 button 天然键盘可达。
- **影响**：新增交互控件的可键盘操作缺口；弹窗主链路（bindNew/会话行/关闭均为原生 button）不受影响，故非阻塞。
- **建议**：分组头改 `el('button', ...)`（对齐 `.nv-ft-row` 惯例，需注意 button 内嵌 span 的样式继承）或最小补丁补 `tabIndex: 0` + `onKeyDown`（Enter/Space）。smoke 断言 `className: 'nv-group nv-bgroup'`（smoke.mjs:1218）与元素类型无关，两种改法均不断言破坏。

### P2-2（建议修改，非阻塞）expanded 以 displayTitle 为键 — 回退态同名组连带开合

- **位置**：`lib/client.js:2090`（`toggleGroup(g.title)` / `expanded.has(g.title)`）+ `lib/client.js:1959`（displayTitle 回退 = path basename）
- **事实**：回退全分组模式下，两个不同工作区可能产出相同 displayTitle（同名 basename 目录或同 title 字段）——展开/折叠其一将**同时开合两组**。当前工作区过滤模式（主路径）恒单组，不受影响。
- **影响**：仅回退态（overview 失败/无命中）下的次要交互瑕疵，无功能损坏。
- **建议**：键改用 `normPath(w.path)`（bindOther 组用固定哨兵串）或组索引，一行级改动。

断言对象是源码字符串而非行为——与套件既有风格一致（UX-013~055 同型），行为面已由 CDP 探针覆盖；未来引入 DOM 测试环境时可重定向为行为断言。当前不改。

### P3-2（讨论）normPath 每 render 重复归一化

`wsList.items.find((w) => normPath(w.path) === curRoot)` 每渲染对每项重新归一化——O(n) 小常数，当前规模（18 会话/数组）无感知；可预建 Map 化。纯优化建议，不要求。

## 三、阻断项

### P1-1（阻断）CTA 章号在 detail 缺失/失败路径上恒为「第 1 章」，且断言把该缺陷写死

**事实链**
- `lib/client.js:3682` `homeChapters = homeDetail?.chapters ?? []`；`:3686` `homeMaxNum = homeChapters.length === 0 ? 0 : …`；`:3687` `homeNextNum = homeMaxNum + 1`
- `:3641-3645` 每次轮询对每本书 `GET /api/novel`，`catch { details[n.id] = null }` —— **失败即永久 null**（下一次轮询前）
- 同页 `:3690` `homeChapterTotal` **已**用 overview 回退（`homeNovel.totalChapters`），但 CTA 章号**未**回退 ⇒ 同一页出现「共 38 章」+「继续写第 1 章」的自相矛盾
- `:3977` 点击把 `homeNextNum` 原样带入意图 → `launchMsgOf` 生成「继续写第 1 章」→ `sessions.prompt`

**影响**：违反用户 2026-10-25「一定要保证所见即所得」的明确裁决，且会产生**错误的 AI 写作副作用**（让 AI 从第 1 章续写一本已有 38 章的书）。

**加重项（断言冻结缺陷）**：`test/smoke.mjs:1396` 断言 `clientSrc.includes('const homeNextNum = homeMaxNum + 1')`——我的 M5 变异（正确修复）**被判红**。这是「断言=实现字面量」的典型失效：修复缺陷必须先改断言，否则回归门禁反向阻止修复。

### P1-2（阻断）首页意图在「分栏已开且同一本书」时被丢弃；残留意图会在后续切书时误触发

**事实链**
- `enterWriting`（`:3824-3830`）：`homeIntent = intent` → `store.set({ selected: homeCurrentId, … })` → `if (novelSplit.active) novelSplit.setBook(homeCurrentId)`
- `setBook`（`:1625-1627`）：`if (this.novelId === novelId) return` —— 同书**早退、不 notify**
- `store.set({selected})` 若已是同值，`selectedId` 不变；`snap.active` 不变
- 消费 effect（`:4305-4313`）依赖 `[snap.active, selectedId]` ⇒ **不重跑 ⇒ homeIntent 不被消费**
- `launcher.open()`（`:2067`）在打开分栏时写 `store.set({selected: novelId})` ⇒ 打开过某书后 selected 即该书

**影响（主路径，不是边角）**：用户「打开书 → 打开工作台 → 点继续写/新建章/待办/最近章节」时，**所有首页动作静默无效**（无提示、无跳转、无工作流触发）。且 `homeIntent` 残留：用户之后切换到另一本书（`selectedId` 变化）时，陈旧意图被消费 ⇒ 对**另一本书**发起「继续写第 N 章」工作流 = 错误 AI 副作用。

**覆盖缺口**：M6 变异（依赖收窄，行为已变）**仍全绿** ⇒ 现有断言只查源码字符串，未覆盖消费时序。既有 `homeIntent` 相关断言（`:1379-1380`）只验证「有 if 分支」「有 launchWorkflow 调用」，对「何时消费」零约束。

## 3. 十项独立核验逐条结论（含复核方式 + 与 Developer 自述是否一致）

### ① 长告警在任何视口都能就地读完 — **成立（不可达截断态）**

- 判据链（实读）：`lib/client.js:3849` 长度判据 `text.length > 24` **或** `:3740` 几何兜底（chip ∩ `.nv-bar-banner` box）⇒ `noticeStream`；`:4140` chip 仅在 `noticeStream !== true` 时渲染；`:4172` 流式面为 `pre-wrap` + `overflow-wrap:anywhere`（`:4808`）无 ellipsis。
- 阈值边界：正好 24 字 ⇒ `24 > 24` 为假 ⇒ 走 chip 分支；**但**该分支是否可见取决于几何兜底（见 ②）——实测 1078 视口 chip 与横幅 box 相交（report `sum=2475.75`）⇒ 升级。25 字及以上恒流式面。
- 含换行/含 emoji：`.length` 为 UTF-16 码元计数（emoji 计 2+），只会**放大**长度 ⇒ 更早升级，方向安全（不产生「长文本走 chip」）。
- 极窄栏：`barW` 由 `colW − max(120, chatW)` 决定（`:3842`；`CHAT_MIN=320`、`LEFT_MIN=120`，`:905-909`），窗口 ≲660px 时栏宽 ≤300px，几何兜底命中（横幅最小宽 ~180px > 可用间隙 43px）。
- **与自述一致**：是。自述「长文本（服务端报文可达数百字）必然截断 ⇒ 长文本一律流式面」有代码级依据。

### ② 残余重叠路径（对抗性检查） — **不可达**（判定见 `RESIDUAL_OVERLAP_PATH`）

构造尝试与代码级排除：

1. **chip 被截断但未触发几何兜底是否可能？** 逐条排除：
   a. chip 渲染 ⇒ A-prime 测量在同一次提交内跑（effect 顺序：`:3712` 声明在前、`:3764` 声明在后 ⇒ 后者在 `noticeKey` 变化时必然执行），且 `measure()` 起始有 `bar/banner/title` 三 ref 空值守卫（`:3713/3719`）——若守卫不满足则 chip 与横幅都不渲染，退化态无重叠对象。
   b. 未截断的 chip（`scrollWidth ≤ clientWidth`）天然把全文呈现在标题栏内，`title` 只是冗余出口 ⇒ 不构成「全文只能靠 tooltip」。
   c. **可用空间算术（实测数）**：1078 视口 report 数据 `chip=(345.61,12,179.39,15)`、`banner=(359.95,?,260.10,?)`、`barW=418`、右簇首个控件 `left=533`。chip 的可移动窗口 = [标题右缘, 533−8=525] ⇒ 右界 525；横幅左缘 359.95 < 525 ⇒ **相交必然**。整块右移被右簇封死（自述「右簇 533→685」与 report 的 `ctl` 数据一致）。
   d. 即便允许 chip 反向收缩：`max-width:46%`（`:4802`）与右簇固定占位共同把 321.95px 宽的 chip 压缩到 ≤180px；唯一「不相交」解要求 chip 完全落在横幅左侧的 14px 间隙内（`t.left≈14`），但**该布局同时迫使 chip 截断到可见 ~1 字符**——即「截断 = 相交」互为充要（实测佐证：`S2-ok-1078x593` 短提示 `sum=1155`、整块落在横幅内）。
2. **唯一两条件同时可满足的退化态** = 横幅 box 宽度为 0（`.nv-bar-banner` 三个子元素全为 null：`titleStageName`/`TitleDot`/`detailStats` 皆空）。此时该 box 与任何元素都不相交 ⇒ 几何兜底不可能触发；但**该状态下横幅「不存在」**，故用户报障的「告警压住上面的文字」重叠在物理上不复现。
3. 结论：**任何可达且「横幅可见」的状态下，被 ellipsis 截断的 chip 必然触发几何兜底升级**；未被截断的 chip 不构成全文不可读。⇒ 残余重叠路径**不可达**（唯一例外态无重叠对象）。**定级：不构成发现**；对代码注释「任何 in-bar chip」的措辞精度提 P3（F-5）。
- **与自述一致**：是，且本审查给出了自述未展开的「截断 ⇔ 相交」充要论证。

### ③ 形态裁决的确定性 / 无抖动 — **成立（P2 观察 F-3）**

- 闩锁复位（`:3701` `setNoticeEscalate(false)` on `noticeKey`）：窄→宽拖动期间同一文本 key 不变 ⇒ 保持流式面**不回落**。用户可预期性：可接受（告警是瞬态、可关闭；关闭即 `setBarNotice(null)` ⇒ key 变 ⇒ 复位；下一条短提示在宽栏下按新几何判形态）。
- 振荡/循环（对照 UX-055 A-prime 先例）：`.nv-bar-banner[data-hidden=true]{visibility:hidden}`（`:4868`）**保留布局盒**（visibility 不触发布局/RO）⇒ 测量口径稳定；`ResizeObserver` 只观察 `bar/banner/title`（`:3750-3752`），chip 的增删与 `.nv-notice` 的增删都不在这些观察目标内；`setState` 值不变时 React bail-out ⇒ **无写→测→写循环**。

- **残余（F-3，P2）**：`noticeKey` 变化时 `noticeEscalate` 先复位为 false，而重新置真必须等测量回调（effect + RO）⇒ 存在**首帧** chip 被渲染的窗口，而此刻 `bannerCollides` 仍是上一次的读数（可能为 false）⇒ 一帧 chip∩banner 可见。实测证据：红/绿两态 report 的 `bannerHidden=null` ⇒ 在拦障场景下横幅本身未被降级，该帧确实会出现叠字（1 帧量级，随后被 `noticeEscalate` 消解）。不影响「长告警恒流式面」主路径（>24 字时 chip 从不渲染）。

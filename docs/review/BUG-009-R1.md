### F1（P2）渲染期外部 store 读取缺 `useSyncExternalStore` 语义

- **事实依据**：`selectNow` 在**渲染期**调用 `resolveStore().getSnapshot()`（`L1374-1378`），`L1418` 每次渲染返回其结果；订阅回调仅 `setTick`（`L1391`）。宿主 React **提供**该 API：宿主自身组件即用 `react.useSyncExternalStore((fn) => popup.state.subscribe(fn), () => popup.state.getSnapshot())`（`@deepseek-ai/dsh-client-ui-commands/lib/client.js:937`），且 `dsh-web-frontend/dist/assets/index-*.js` 亦含该符号 ⇒ 宿主 React ≥18 且 API 可用（**版本号未直读**，以 API 调用点为据）。改动前实现在 `useEffect` 回调里读取（`git show bd913b7:lib/client.js` L1387-1389），因而不存在渲染期读外部 store 的问题。
- **影响**：并发渲染被中断/让出期间若 store 发生变更，同一提交内不同组件可能读到不同快照（tearing）；表现为**瞬时**不一致（下一次通知自愈），无实测发生（49 条探针项 + 293 条 smoke 均无 tearing 判据，探针亦无渲染计数指标）。不含数据损坏面。
- **修复建议**：改用 `useSyncExternalStore` 取**原始快照**、selector 在渲染期套用：

  ```js
  const snap = useSyncExternalStore(subscribeForCurrent, () => { const st = resolveStore(); return st === null ? EMPTY : st.getSnapshot() })
  return snap === EMPTY ? undefined : selector(snap)
  ```

  注意两条约束（否则会引入新缺陷）：① `getSnapshot` **不得**返回每次新建的对象（React 会判"持续变化"而无限重渲染）⇒ selector 必须留在 `getSnapshot` 之外（现状 F3 的两个新建容器 selector 正是反例）；② 服务增减/holder 惰性解析需用一个稳定的 `subscribe` 包装（服务切换时换订阅仍由 `refresh()` 驱动）。若不本轮实施，建议登记为遗留项 + 记 `risk-log`（级别 P3：无实测发生）。

### F2（P3）重渲染放大（如实披露的取舍）

- **事实依据**：`bump = () => { if (!disposed) setTick((n) => n + 1) }`（`L1391`），`resync()` 末尾无条件 `bump()`（`L1408`），`refresh()` → `resync()`（`L1421-1423`）；旧实现的 `read()` → `setValue` 会在 `Object.is` 相等时 bail-out。**构造性量值**（同一 mini-react harness 重放）：新实现 `renders=4`、旧实现 `renders=2`（挂载 +1、通知 +1）。
- **影响**：每次 store 通知与每次挂载多一次渲染；无自激循环（effect deps `[]`，`selectNow` 无副作用写入）。无通知频率/长帧实测数据 ⇒ **不做劣化主张**。
- **修复建议**：维持现状（同时服务 BUG-005「派生值不变也强制重渲染」契约）；若后续有性能观测（宿主会话高频更新场景），再评估给 hook 加可选 `eq`/选择器记忆化——本任务未加属如实披露的范围控制，**不判缺陷**。

### F3（P3）selector 返回值身份：从「每通知」变为「每渲染」

- **事实依据**：`L2643` `(s) => (Array.isArray(s.ids) ? s.ids : []).map((id) => s.byId[id])`、`L3098` `(s) => ({ ids: …, byId: s.byId ?? {} })` 每次调用都产生新身份；消费点经只读检索确认**全在渲染体内**：`entries`（`L2759/2768/2770/2805`）、`sessionsAll`（`L3394-3397` 计算 `foundSessions` 后直接渲染）；全仓 `memo(`/`React.memo` = 0；`useEffect` deps 依赖的 hook 值仅 `sessionsCurrent`/`splitCurrent`（`L3131`、`L3833`），二者为 string|null 基元。

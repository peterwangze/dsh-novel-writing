### 3. 会话联动守卫（last-non-null）— ✅ 五形态语义 + 豁免令牌逐行对照通过

`shouldCloseOnCurrentChange`（lib/client.js 新增纯函数）+ 两处调用方（NvConsole L2605-2623 / SplitWorkspace L3266-3285）：

| 形态 | 结果 | 依据 |
|---|---|---|
| X→null→Y（跨工作区） | 关 1 次 | null 步：next=null→false 且基准保持 X；Y 步：X≠Y→true |
| null→X（就位） | 不关 | prev=null→false；基准推进 X |
| X→X | 不关 | 相等→false |
| X→Y（同工作区） | 关 | 不等→true |
| X→null→X | 不关 | null 不刷基准；X===X |

- 与旧逻辑差异仅在「null 过渡不刷新基准」（正是修复目标）；seeded 首帧 null 不写基准（useRef 初值 null）与旧「prev=null 仅刷新基准」行为等价。
- 豁免令牌语义保持：关闭分支的进入条件（prev 非空 ∧ next 非空 ∧ 不等）与旧代码等价，`pluginOpened`/`pluginOpenTokens` 的 has→delete 一次性消费原样迁移（L2617-2619 / L3279-3281）。
- effect deps `[sessionsCurrent]` / `[splitCurrent, snap.active]` 保证守卫随 current 变化执行；卸载重挂 ref 重置→重新 seed，防误关语义保持。
- 修复根因确认：旧逻辑 X→null→Y 中 Y 到达时 prev 已被 null 覆盖 → 不关（吞掉真实切换）；新逻辑保留 X 基准 → 关。✅

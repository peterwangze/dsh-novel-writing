## 3. 守卫判断（有效、克制、非全局解析器）

### 3.1 机制复核

守卫只做三件事，范围明确：

1. 用 `/\.nv-split\{([^}]*)\}/` 取**首个** `.nv-split{...}` 块（当前即 L6192 布局单一事实源），提取块内 `--nv-*:` 声明；
2. 在 `outside = clientSrc.replace(block, '')` 中按 `var(--x)` / `var(--x,` / `cssVarNum('--x')` / `cssVarNum("--x")` 四通道要求每个声明至少 1 处消费；
3. 同时断言三向：`unregistered`（未登记新增）、`missing`（预期变量被删）、`dead`（零消费），已知集固定 10 项，`LAYOUT_VAR_ALLOWLIST = new Set()` **为空**。

判定：**通过**。它没有尝试解析全局 CSS，不含嵌套/跨文件解析，失败面收敛在「布局变量声明与消费」这一本轮验收口径，符合 R3 P2-1 的「把 CSS 变量消费面加入 smoke 单一事实源 gate」建议；与既有 UX-061 尺度令牌守卫、契约 `regionLiterals` 看护互补，不重复造解析器。

## 4. P1 阻断项

### P1-1 §9「detail 空但 overview 章数 >0」仍被渲染成 0 章新书（产品阻断）

`homeDetailStale` 在 [lib/client.js](../../lib/client.js#L4020) 已正确识别：

```js
const homeDetailStale = homeDetail !== null && Array.isArray(homeDetail.chapters) && homeDetail.chapters.length === 0
  && (homeNovel !== null && typeof homeNovel.totalChapters === 'number' ? homeNovel.totalChapters : 0) > 0
```

但全文件只有 4 处命中：两个 i18n 文案键、这一处计算、L4466 的 `detailNote`。**这个 flag 没有被任何展示 / 禁用 / 保存 / 待办分支消费**。于是 stale 时实际表现：

| 面 | brief 要求（S1-fix-brief L213 / L22） | 实际 | 位置 |
| --- | --- | --- | --- |
| eyebrow | hero 用 overview 真值；不得说“还没有章节” | `lastNum===null` ⇒ `还没有章节` | [L4507](../../lib/client.js#L4507) |
| 元信息章数 | `38 章`（overview） | `0 章`（`homeChapterTotal===0`） | [L4490](../../lib/client.js#L4490) |
| 主 CTA | **disabled**，不得猜“写第 1 章” | `homeChapterTotal===0 && homeNextNum===1` ⇒ 显示“写第 1 章”；`disabled` 只判 `homeDetail===null || homeNextNum===null`，stale 时 **enabled**；点击进入 `workflow:'continue', chapter:1` | [L4477-L4479](../../lib/client.js#L4477)、[L4527-L4529](../../lib/client.js#L4527) |
| 保存时间 | `保存时间未知` | `尚无保存记录` | [L4482-L4483](../../lib/client.js#L4482) |
| 书案线待办 | `— 章未发布` | `0 章未发布` | [L4617](../../lib/client.js#L4617) |
| 书架卡章数 | overview 的 `38 章` | 每本 stale 书 `deriveHomeChapterTotal(d,n)` 仍返回 `0 章` | [L4579](../../lib/client.js#L4579)、[L4599](../../lib/client.js#L4599) |
| 搜索书行 | overview 章数，不伪造 0 | `detail !== null` 直接取 `chapters.length` ⇒ `0 章` | [L4045-L4049](../../lib/client.js#L4045) |
| 引文卡 | 空 | `homeQuoteNum===null` ⇒ empty，**唯一正确项** | [L4468-L4470](../../lib/client.js#L4468) |
| note | `章节数据未就绪` + 重试 | 正确 | [L4464-L4466](../../lib/client.js#L4464) |

纯函数复现（从 `#region home-model` 提取后真跑）：

```json
{
  "stale_empty_chapters": {
    "nextNum": 1,
    "chapterTotal": 0,
    "todo": { "unpublished": 0, "gateFails": 0, "gateFirstNum": null },
    "recent": []
  },
  "null_detail": {
    "nextNum": null,
    "chapterTotal": 38,
    "todo": null,
    "recent": null
  }
}
```

`deriveHomeChapterTotal({chapters:[]}, {totalChapters:38})` 返回 `0`，而注释 L826 声称“未就绪回退 overview”；实现只对 `detail===null` 回退，`chapters:[]` 被当成真实 0 章。`deriveHomeNextNum` / `deriveHomeTodo` 同样把 stale 当 0 章新书，只有 `detail===null` 才返回未知。这就是上面 CTA 可用、0 章、0 待办的根因。

可达性：`lib/index.js` 的 overview 取 state 统计（L417-L418），detail 取 `chapterList`（L437）；`updateState` 又写统计（L1003-L1004）。外部删除 / 状态漂移会造成 overview `totalChapters>0` 而 detail `chapters:[]`。这不是只存在于理论里的形状，而是 brief 明确要求处理的双源不一致；即使无法在固定夹具中稳定复现，也不能把禁止的 0 章写进产品。

证据等级：这是**代码路径 + 纯函数证据**，不是真实 stale 截图；我没有在真实宿主构造出 stale 并截图。它足以判 FAIL，因为代码分支和纯函数输出已直接违反验收条款。

- 暗色三主题的选中面边界全部 <3:1；浅色三主题 >=3:1。开发报告 §5 只举了墨纸 `light 5.70 / dark 1.81`，实测青简/夜航暗色也在 2.0 左右，结论相同且更完整。
- 作为对比：R2 的 6% 软底对相邻面仅约 **1.03:1（暗色）/ 1.10:1（浅色）**；R3 实底把暗色边界提升到 1.81~2.04，**是改善但仍未达 3:1**；浅色提升到 5.14~5.90。因此 P2-5b 不是 R3 新引入的回归，而是 R2 残余边界在 R3 后仍未闭合。

### 5.2 按 WCAG 1.4.11 的判定

参考：W3C, [Understanding SC 1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)（2026-11-09 取用）。

WCAG 2.2 SC 1.4.11 的规范文本要求：

> The visual presentation of the following have a contrast ratio of at least 3:1 against adjacent color(s): **User Interface Components** — Visual information required to identify user interface components and states…

W3C《Understanding SC 1.4.11》进一步说明：

> … any visual information necessary to indicate state, such as whether a component is selected or focused must also ensure that the information used to identify the control in that state has a minimum 3:1 contrast ratio.

> It is possible to use a flat design where the status indicator fills the component and does not contrast with the component, but does contrast with the colors adjacent to the component.

> This success criterion does not require that changes in color that differentiate between states … meet the 3:1 contrast ratio when they do not appear next to each other.

- 本控件的「选中」非文本指示就是**实底填充**；选中 chip 与未选中 chip **相邻**，所以「状态色不相邻」的豁免不适用。反过来说，平坦设计中状态色填满组件时，它必须对**相邻颜色**有 3:1——正是上表暗色 1.81~2.04 失败的情形。
- 「控件不需要边界指示点击区」的例外（Understanding 的 *Boundaries* 段）针对的是**识别控件存在**的 hit-area 边框；这里文字数字已经能识别控件存在，但**选中状态**的填充仍是非文本状态信息，不能用该例外豁免。1px 同色环更不能充当边界。
- 替代豁免不成立：选中态确实另有 600 字重和文字颜色变化，但它们不是 3:1 的非文本边界，且 12px 的 600 字重对低视力不足以替代整块填充的明度差。因此**按严格 1.4.11，这是真实的 AA 不达标，不应以「填充只是装饰」解释过去**。
- 级别判断：它是 **P2 残余**，不是 P1。理由：文字可读性已修复（5.41:1）；无行为/数据/布局破坏；R3 未引入新的不可读文字；问题在 R2 的 6% 软底/环上就已存在，R3 只是没有顺带解决环/边界。但它**阻断 WCAG AA 声明**，并在项目把 AA 作为完成条件时**阻断 UX-067 完成**；建议后续为选中态增加一条对相邻未选中面 ≥3:1 的独立边界（外描边/加深实底/独立环），并同时核对环对内实底与对外相邻面；具体色值需按两邻接面复算（例如暗色 `--nv-paper-2` 对宿主 overlay 仅约 2.99:1，不能仅凭令牌名假定通过）。R3 不要求实现该项。

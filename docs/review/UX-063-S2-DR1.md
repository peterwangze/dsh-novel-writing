## 3. Findings

### P1-1（阻断）数据未就绪即当真值并放行操作 —— 直接违背裁决②
**位置**：`lib/client.js:3681`（`homeDetail`）、`:3686-3691`（派生）、`:3974-3981`（CTA/新建章渲染，**无 disabled 守卫**）
**事实链**：
1. `details` 来自 `poll.data`（`:3648-3649`），首轮 `poll.data === null` ⇒ `novels = []` ⇒ `homeNovel === null` ⇒ 首页渲染 `homeNoBooks`（`:3955-3956`）——**加载中被显示成「无书目」**（假空态；smoke 渲染树断言 `test/smoke.mjs:1324` 已把该行为固化为预期）。
2. 某本书 detail 拉取失败时 `details[id] = null`（`:3643` catch），于是 `homeDetail === null` ⇒ `homeChapters = []` ⇒ `homeMaxNum = 0` ⇒ **`homeNextNum = 1`**，界面显示「继续写第 **1** 章」/「新建第 **1** 章」，并且 **按钮可点**（`:3974-3981` 无 `disabled`）。
3. 点击即经 `launchMsgOf` 发出「继续写第 1 章」——对一本已有 38 章的书，这是**错误指令 + 真实 AI 副作用**；同屏的「未发布 0 / 门禁 0（置灰）」也把「数据缺失」显示成「状态良好」。
**判定**：这不是瞬时抖动（首轮加载由 `poll.data` 一次性拉齐 overview+全书 detail，正常路径渲染时 detail 已在位），而是**可表示的失败态**（单本 detail 失败/接口异常）被静默当作真值并驱动操作。
**修法建议（任一，成本均在 10 行内）**：
- `homeDetail === null` 时：CTA/新建章 `disabled` + 文案降级为「数据加载中/重试」，待办三项显示 `—` 而非 `0`；
- 或 `homeNextNum` 改由「detail 章号 max+1，detail 缺失时回退 `overview.totalChapters`（并在 UI 标注口径）」派生，但**不得**在无依据时给 1；
- 加载态与真空态分离：`poll.data === null` 显示骨架/占位，`homeNoBooks` 只用于「确实 0 本」。

### P2-1 行为面断言强度不足（用户裁决无行为级覆盖）
`test/smoke.mjs:1362-1381` 等为**源码字符串 / 函数体切片**断言；唯一渲染树断言（`:1310-1329`）只覆盖**空态**（`.nv-home-empty`，CTA 不渲染）。后果：裁决①② 的「真触发」「所见即所得」**没有任何渲染或交互级证明**，P1-1 这类数据态缺陷正是该强度抓不到的。
建议（沿用仓内既有能力，不新增依赖）：用 slot 渲染通道以 mock overview+detail 渲染一次首页，断言四区存在、CTA 文案含 `max+1`、点击 CTA 后产生 workflow 意图（可断言 `homeIntent` 消费或 `pendingWorkflow` 置位）；再补一条 detail 缺失态的渲染断言（P1-1 修复后的禁用态）。

### P2-2 加载中「无书目」误报（见 P1-1 第 1 点）
独立列出以便跟踪：`poll.data === null` 与「确实 0 本」共用同一空态视觉与文案，用户可能误判书目丢失。

### P2-3 口径混源未在 UI 标注
`homeChapterTotal` 用 detail 优先/回退 overview（`:3690`，注释已写明口径），但「字数」恒取 `homeNovel.totalWords`（overview，`:3966`），「章数」可能取 detail 长度——两行同屏出现时若两源不同步，读者会看到轻微自相矛盾。建议同一卡片内统一来源或在同批标注刷新时点。

## 二、新引入检查

1. **基类 `background:transparent` 对 button UA 样式的影响**：显式声明覆盖 UA 默认背景，与 HEAD 行内 transparent 等效（默认态透明不变）；无 side effect ✓。
2. **rgba(79,142,247,.9) 与 88% color-mix 视觉等价性**：核算——88% mix = `0.88×(79,142,247) = (69.5,125.0,217.4)`（不透明）；rgba .9 叠于暗底（bg-base #0b0e14）= `0.9×(79,142,247)+0.1×(11,14,20) = (72.2,129.2,224.3)`；Δ每通道 ≤7/255（≈2.7%），ΔE 视觉阈值边缘下 → **近似等价声明属实**（更精确值 α≈0.88，但 .9 在容差内且保留"hover 有反馈"底线——比 R1 前"无反馈"是本质改进）；注释 L3595 更新为「先 rgba 兜底后 color-mix 双声明（Chromium<111 回退为 90% accent 近似，不丢失 hover 反馈）」与实现一致 ✓。
3. **新增发现 G1（P2，R1 遗漏补记）**：`.nv-chrow:focus-visible{outline:none;box-shadow:双环}`（当前源码 L3621，特异性 (0,2,0)）与 `.nv-chrow[data-sel=true]{...;box-shadow:inset 2px 0 0 0 accent}`（L3622，同特异性 (0,2,0)、源码序在后）——同特异性平级、后者胜出 → **选中章节行键盘聚焦时双焦点环被 inset 边条覆盖**，仅剩 2px 边条（outline:none 已在 focus-visible 内生效）。影响：键盘 Tab 至已选中行（含默认选中的 list[0]）时无标准焦点视觉；文件树行（ft-row data-sel 仅 background，无 box-shadow）无此问题。修复建议（下轮）：调序（focus-visible 规则置于 [data-sel] 之后）或对选中行聚焦合并 box-shadow（双环 + inset）。**定级 P2（非阻塞）**；此缺陷随 R1 提交引入（本轮审查补记，非本次返工新引入）。
4. **夹带检查**：R2 diff 相对 R1 diff 的差异仅限上述返工点（chrow/ft-row 内联删除、CSS 基类与 data-sel 增补、cbtn-accent/bar-launch 双声明、smoke +2 断言及相应注释）——P2/P3 遗漏项区域零改动，**无超范围夹带** ✓。

### 3.2 实际渲染，而不是只读 computed string（本轮关键）

**几何报告里出现的非法字体族名**：G4 `MEASURE` 的 `typo.*.fontFamily` 是 `"\"'Noto Serif SC'\", \"'Source Han Serif SC'\", …"`——族名里带字面单引号。根因不在产品：

- [scripts/verify-visual-geometry.mjs L39-L41](../../scripts/verify-visual-geometry.mjs#L39) 用 `/':root\{([^\n]*?)\}',/` 从**源码原文**抽取 `rootCss`，把 JS 单引号字符串里的 `\'` 转义原样拼进 HTML `<style>`；CSS 把 `\'` 解释为标识符里的引号字符，于是族名变成 `'Noto Serif SC'`（含引号），匹配不到任何已安装字体，最终落到 generic `serif`/`sans-serif`。
- 产品源码按 JS 求值后是合法的 `--nv-serif:'Noto Serif SC','Source Han Serif SC',…`：我独立用 `eval` 取 [L6140](../../lib/client.js#L6140) 的字面量，得到无 `\'` 的合法 CSS；真实宿主 `getComputedStyle(.nv-content).fontFamily` 也是 `"Noto Serif SC", "Source Han Serif SC", "Songti SC", STSong, SimSun, serif`（无嵌引号）。
- 因此 geometry 的 `typoVariants`（[L751-L758](../../scripts/verify-visual-geometry.mjs#L751)）靠 `includes('serif sc')`/`includes('kaiti')` 子串仍会通过；`typoNoOverflow` 的 450/680 18px 实际量的是 generic 回退字体，不是四套目标字体。**这是测试保真缺陷（P2-1），不是产品 P1**。

**真实渲染字体（CDP `CSS.getPlatformFontsForNode`，真实宿主）**：

| 选择 | 真实宿主 computed fontFamily | 正文 `<p>` 实际 platform font | 预览实际 platform font |
| --- | --- | --- | --- |
| serif / 16（A2） | `"Noto Serif SC", "Source Han Serif SC", "Songti SC", STSong, SimSun, serif` | **Noto Serif SC**（8 glyphs） | **Noto Serif SC**（4 glyphs） |
| sans / 17（A3） | `"Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif` | **Noto Sans SC** | **Noto Sans SC** |
| kai / 18（A5） | `"Kaiti SC", STKaiti, KaiTi, "Noto Serif SC", serif` | **STKaiti** | **STKaiti** |
| system / 15（A6） | `system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif` | **Microsoft YaHei UI** | **Microsoft YaHei UI** |

- 菜单四行字体样本的实际 platform font 也分别是 Noto Serif SC / Noto Sans SC / STKaiti / Microsoft YaHei UI（A2 审计），四行视觉可辨。
- 「正文预览」在 serif/16 的 computed `fontStyle=normal`、`fontWeight=400`、`transform=none`；实际 platform font = Noto Serif SC。它看起来略斜是 Noto Serif SC 在 16px/灰度合成下的字形观感（与静态 Noto Serif SC 16px 样本形状一致），**不是 italic、不是 fallback、不是另一个字体**。本机「宋体」首命中是已安装的 Noto Serif SC，不是 SimSun；这符合批准栈的第一可用族，属设计口径（P3-5 仅记录）。
- textarea 的 CSS computed 与正文同源（17px/sans；A4），但 `CSS.getPlatformFontsForNode` 对 textarea 返回 `[]`（其 value 不是 DOM text node），无法直接取实际字体；以 computed + 编辑态截图 + 文本宽 544 双判据覆盖，未发现回退证据（P3-6 观测边界）。
- 结论：四档选择**实际改变 glyph 来源**，不是只改字符串；任务中「font control 只改 computed string」的 P1 触发条件不成立。

# UX-061 视觉验收目检清单（G-5，需人工在真实宿主执行）

**用途**：方向 A 视觉交付的唯一剩余门槛。**目检未通过前，A 迭代不得宣称「视觉验收通过」**（DR3/DR1 定稿口径：代码面完成、验收待人工目检）。
**前置**：DSH Web 已运行（当前 `http://127.0.0.1:3080`）；如刚更新插件代码，先重启宿主。
**判据来源**：`REVIEW-UX-061-1B-DR3` / `REVIEW-UX-061-1B2-DR1`（专项目检项由设计审查点定）。

## A. 主题矩阵（每项都要看明 + 暗两种）

| # | 检查 | 预期 | 失败判据 |
|---|------|------|----------|
| A1 | 亮色下表面/卡片是否可见 | 卡片有可见边界与层级，悬停有可感知变化 | 白底上「看不出卡片」= 令牌桥仍未生效 |
| A2 | **亮色卡片层级**（DR 专项） | 卡片与页面层级靠 1px `border-strong`（≈1.26:1）+ hover；可辨但不刺眼 | 完全分不出卡片与背景 / 边框过重像表格 |
| A3 | **hover 可感知性**（DR 专项） | hover 时**边框或前景**变化可感知（accent 边框） | 只有极轻微底色变化（tint 单独仅 1.11:1）⇒ 视为不达标 |
| A4 | 状态色文本可读性 | success/warn/error 文本在浅底 chip 上清晰可读 | 颜色发灰、与底色接近 |
| A5 | 主按钮文字 | 按钮上文字与底色对比清晰，亮/暗都不「白字贴白底」 | 文字与按钮底色接近 |

## B. 四视图（管理台 / 创作台 / 数据 / 发布）

| # | 检查 | 预期 |
|---|------|------|
| B1 | 管理台书目卡片 | 无渐变、无重阴影；卡片名称/状态/元信息三层清晰 |
| B2 | 创作台工作流控制条 | 状态 chip 三档语义清楚（muted 待办 / running 进行中 / err 阻塞）；按钮行高一致 |
| B3 | 数据面板标题 | 20px 且与下层数值形成层级（不再和正文同号） |
| B4 | 发布面板 | 状态与操作区层级清楚，无字号跳变 |
| B5 | **表单行高度配对**（DR 专项） | 同一行内输入框与按钮视觉上等高（当前实现：输入 32 / 按钮 28，已知 4px 差） |
| B6 | **+1px 换行检查**（DR 专项） | 固定宽控件（`.nv-chip` / `.nv-csortbtn` / `.nv-wfchip` / 书卡 meta）不因 13→13.5 / 14→15 而换行或截断 |

## C. 七态（空 / 载入 / 正常 / 错误 / 阻塞 / 完成 / 部分）

## 失败时的最小定位材料

1. 截图（能看层级/字号/颜色关系即可）
2. 出错视图名 + 明/暗
3. 若涉及对比度：指出是哪段文字（如「书卡状态文字」「告警 chip」）

> 处置口径：任一项失败 → 记录到本清单并在 plan-tracker 开修复项；**只有全部通过（或问题已登记且用户接受）才可宣称 A 迭代视觉验收通过**。

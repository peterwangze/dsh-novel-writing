## 结论一句话

**0.2.2-rc.1 的浮层槽协议没有变——`shell.overlay` 仍是文档化 list 槽且宿主照常消费；BUG-012 的真根因是插件自身的 Rules-of-Hooks 违规（`lib/client.js` SplitWorkspace：L4674 条件早退 `return null` 之前缺 hook、L4797 `useEffect` 在早退之后），点书卡使 `snap.active` false→true 翻转时 React 18.3.1 抛 minified error #310（Rendered more hooks than during the previous render），宿主 SlotErrorBoundary 捕获后卸载整个 novel-split entry ⇒ 用户看到「工作台不在」。**

### 3. 违规定位（源码级）

`lib/client.js` SplitWorkspace（L4412 起）：

- L4674：`if (snap.active !== true) return null`（UX-006 引入的合法早退）；
- L4797：`useEffect(() => { … launchWorkflow … }, [pendingWorkflow])`（**UX-063 P0-a 第②步（commit 370a100，v0.5.3 后未发布）引入，位于早退之后**）。

挂载渲染（inactive）hook 数 = N；点书卡 → `snap.active` true → 渲染跑到 L4797 时上一渲染 hook 链耗尽 ⇒ #310。静态审计（83 个组件函数全扫）确认**全文件仅此一处**「早退在前、hook 在后」违规。

- 引入时间线 ⇒ 与宿主代无关：**同一违规在 0.1.x/0.2.0/0.2.1/0.2.2 上都会炸**；0.2.1 时代的浮层验证证据（BUG-011/UX-012）全部早于 UX-063 第②步（2026-10-25），彼时该 effect 尚不存在。
- 既有测试为何没拦住：违规只在「挂载后 inactive→active 转换」触发；直测/几何测试多以 active 态首帧挂载（hook 数恒定）⇒ 不触发。

## 双表面适配方案（按事实修正后）

**无需双表面适配**——新旧宿主消费面相同且都在工作。修复方案（阶段 B）：

1. `lib/client.js`：把 pendingWorkflow 消费 effect **上移到全部条件早退之前**（hooks 恒定调用契约）；`launchWorkflow` 仍定义在下方（依赖 active 态派生值），经 `launchWfRef`（useRef）间接调用；effect 以 `snap.active` 门控——inactive 时**保留**意图不清空，active 翻转经 deps 变化消费（语义与旧「hook 挂载即消费」等价且不再依赖违规时序）。
2. 降级路径（「不再静默」的落点）：真根因修复后无「宿主不支持浮层」面；宿主 SlotErrorBoundary 卸载 entry 时的静默是宿主行为，我们侧的防再犯 = smoke 静态守卫（见 3）。
3. `test/smoke.mjs`：新增 Rules-of-Hooks 静态守卫（组件函数「顶层早退在前、hook 调用在后」检测，断言全文件 0 违规 + 负例判别力对照），断言数如实 bump。

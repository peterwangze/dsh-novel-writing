# Publish Pipeline（多平台发布流水线）

源工作流 v4.2 的已知限制：「数据监控依赖用户手动提供平台数据，无法自动读取平台后台」。本 Skill 定义插件如何把发布与数据获取从"全人工"升级为"半自动 + 可配置全自动"，并明确哪些能做、哪些受平台限制。

## 发布模式（设置 → 小说写作 → 各平台配置）

| 模式 | 行为 | 适用 |
|---|---|---|
| `export`（默认） | 生成 `dist/<平台>/chapter-NNN.md/.txt` 定稿产物 + `发布清单.md` | 人工粘贴；首次发布 |
| `command` | 导出后执行配置的命令（环境变量：`DSH_NOVEL_DIR`/`DSH_PROJECT_DIR`/`DSH_DIST_DIR`/`DSH_PLATFORM`）| 有自研/开源自动化脚本（Playwright 粘贴、平台 CMS 接口）|
| `manual` | 仅生成发布清单 | 想完全手工走一遍 |

**发布前硬校验**：`release_allowed === true`（AI 合规路径 A）。`novel_publish` 在代码层拒绝未通过合规门禁的发布，不能绕过。

## 发布流程（你执行）

1. 存稿达标检查（发布策略：10-30 章存稿）→ 用户在 `ask_user_question` 确认发布时间表；
2. 校验发布章节的连续性账本：最新通过章节 → 待发布章节无 gap；
3. `novel_publish {platform, chapters}` 导出产物；
4. 人工模式：把 `发布清单.md` 呈现给用户（逐章 checklist）；命令模式：跑自动化，读 `commandResult`，失败时把 stderr 给用户并降级为人工；
5. 发布完成后回写 `11-data-monitoring/` 观测基线（首日数据）并开始 `data-monitoring` 阶段。

## 数据抓取配置（数据回流）

- 每个平台可配 `fetchCommand`：stdout 输出 JSON 行 `{"date":"2026-05-01","完读率":12.3,"追读":58,"日增收藏":15,"收益":120}`；
- 推荐数据源分级（按可自动化程度从高到低）：
  1. **平台后台导出/复制**（所有平台都支持，半自动）：把后台数字粘贴到工作台「数据」表单或 CSV → `novel_data_ingest`；
  2. **fetchCommand 脚本**：自建浏览器自动化（作者助手/作者后台登录态）或平台 API（如有）→ 输出 JSON 行；
  3. **竞品/榜单爬取**（web_search 现状数据，只用于调研阶段，不进流程指标）。
- 诚实边界：番茄/起点/晋江/七猫**没有公开的作者数据 API**；自动化能力=后台页面脚本化（有封号风险，必须用户知情同意）；政策敏感场景（AI 内容治理）优先人工核对最新官方规则。

## 合规与风险

- 发布前再次核验目标平台最新 AI 政策（web_search），源工作流的历史阈值（存稿量、签约条件）必须标注"请核实最新标准"；
- 合同陷阱 11 条进 `14-launch-strategy.md` 检查清单（自动续约/优先购买权/竞业限制/广告权/独家范围）；
- 导出的章节包含「本章字数」尾部统计，与平台后台字数差异需人工复核（不同平台计字规则不同）。

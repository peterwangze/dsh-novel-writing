# Chapter Outline Skill

生成章节细纲，为正文生成提供详细指导。

## 执行人设

你是一位精细的剧情设计师，擅长将宏观大纲转化为可执行的具体章节。你注重前后连贯性、场景细节和情感节奏，生成的细纲能够直接指导正文写作。你的特点是注重爽点设计和章末钩子，保证读者粘性。

## 触发条件

- 大纲确认完成后
- 用户明确请求细纲生成
- 工作流进入 chapter_outline 阶段

## 前置依赖

- workflow-state.json 中 outline_writing 阶段已完成
- 05-outline.md 存在
- 人物设定和世界观文件存在

### 4. 细纲模板

每章细纲保存为 `novel-project/06-chapter-outlines/chapter-XXX.md`：

```markdown
# 第X章：[章节名]

## 基本信息
- 所属卷：第X卷
- 字数目标：[字数]字
- 预计爽点：[爽点类型]

## 章节概要
[100-200字的章节概要]

## 详细情节

### 场景一：[场景名]
- 地点：[地点]
- 时间：[时间]
- 出场人物：[人物列表]
- 情节内容：
  [详细描述]

### 场景二：[场景名]
[同上结构]

## 人物出场

| 人物 | 出场方式 | 本章作用 | 情绪状态 |
|------|----------|----------|----------|
| [人物] | [方式] | [作用] | [状态] |

## 关键对话
[需要出现的关键对话或台词]

## 伏笔/呼应

### 本章埋设
- [伏笔内容] - 预计第X章揭示

### 呼应前文
- 呼应第X章：[内容]

## 爽点设计
- 爽点类型：[打脸/升级/装逼/反转等]
- 爽点位置：[场景]
- 爽点铺垫：[如何铺垫]
- 爽点释放：[如何释放]

## 章末钩子
[吸引读者继续阅读的悬念或钩子]

**钩子强度**：[强/中/弱]
- 强：揭示让读者无法不翻页的信息 + 制造"必须知道答案"的认知缺口（带悬念的章节结尾追读率高22%）
- 中：留下未解问题但冲击力一般
- 弱：章节自然收束、无强驱动力的结尾
> 规则：连续3章弱钩子=弃书高风险区。前5章至少4章为强钩子。
> 数据：前50页流失44%读者——这是最大流失区，前5章的钩子密度直接决定生死。

## 付费转化设计（付费章节专属）
- 钩子类型：[悬念卡点/高潮前卡点/反转卡点/升级卡点]
- 本章在付费转化中的角色：[免费最后章吸引付费 / 付费第一章即时回报 / 付费常规章维持追读]
- 预期转化强度：[高/中/低]
- 风险提示：[该章可能导致退款的因素，如无则填"无"]

## 推荐触发点设计
- 社交传播触发点：[本章是否有读者会主动截屏/分享的段落？描述位置和内容]
- 段评引爆点：[本章是否有引发评论区讨论的争议点、谜题或吐槽点？]
- 社交货币类型：[推荐本章会让推荐者显得____（有品味/懂行/幽默/有见识）]
> 数据支撑：高唤醒情绪（敬畏/惊喜/愤怒）驱动分享。低唤醒（悲伤/满足）抑制分享。爆款作品每章至少1个触发点。

## 注意事项
[写作时需要注意的事项]
```

## 上下文管理

### 加载策略

| 内容类型 | 加载方式 |
|----------|----------|
| 大纲 | 加载完整大纲 |
| 人物设定 | 加载主要人物完整设定 |
| 世界观 | 加载完整世界观设定 |
| 已有细纲 | 加载前5章细纲摘要 |

### 上下文监控

在生成前检查上下文状态：

```
上下文检查：
- 生成范围：第X-Y章
- 已有细纲：N章
- 加载内容大小：[预估token数]
- 状态：[安全/警告/超限]
```

### 压缩触发条件

| 状态 | 触发条件 | 处理方式 |
|------|----------|----------|
| 安全 | 预估 < 60% 限制 | 正常加载全部设定 |
| 警告 | 预估 60%-80% 限制 | 使用摘要版设定 |
| 超限 | 预估 > 80% 限制 | 触发压缩机制 |

### 压缩机制

#### 第一级压缩：摘要模式

1. **大纲摘要**：只保留分卷大纲核心点
   ```markdown
   # 大纲摘要
   当前卷核心冲突：[冲突]
   主角当前目标：[目标]
   关键人物：[人物列表]
   ```

2. **人物设定精简**：只保留主要人物的精简信息
   ```markdown
   ## [人物名]（精简）
   - 身份：[身份]
   - 性格关键词：[3-5个词]
   - 当前发展线：[简述]
   ```

#### 第二级压缩：最小模式

1. **极简大纲**：只保留当前卷的一句话概述
2. **核心人物**：只加载主角设定
3. **分批生成**：减少每批章节数

### 分批优化

当生成大量细纲时：

```
检测到需要生成[X]章细纲，根据上下文状态建议：

当前上下文状态：[状态]
建议批次：
- 方案A：每批5章，共[N]批（推荐）
- 方案B：每批10章，共[M]批（需压缩）

请选择：
1. 采用推荐方案
2. 自定义每批章节数
3. 尝试一次性生成（可能触发上下文问题）
```

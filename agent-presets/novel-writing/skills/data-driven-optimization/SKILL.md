# Data-Driven Optimization（数据驱动动态优化）

「数据不会告诉你这本书好不好，但数据会告诉你读者在哪一页开始走神。」——data-analyst

## 触发源

1. `novel_data_ingest` 返回的信号（宿主按阈值表计算）：完读率低、章节流失、追读下降、收藏停滞、收益下滑；
2. 用户从工作台提交的 `data` 请求；
3. 读者评论（`12-reader-interaction/`）中的差评集中（同一问题 ≥3 条）。

## 闭环：发现 → 定位 → 对策 → 用户确认 → 执行 → 验证

### 信号 → 对策映射（阈值见数据监控 skill，机械阈值由宿主代码执行）

| 信号 | 定位动作 | 对策（写作方向/内容调整） | 验证 |
|---|---|---|---|
| 完读率低（10万字<10%） | 重审前 3 章（开篇结构/钩子/人设入场）| `opening-optimization` 专项；必要时开篇重写方案（用户确认）| 改后 7 天观察完读率 |
| 章节流失（某章读完率<30%）| 该章诊断：节奏/钩子/内容与读者预期错位 | 该章重写或「补钩子」修订；若为设定问题 → 大纲/细纲层调整 | 重写后再看该章读完率 |
| 追读下降（连续3天>10%） | 最新 3 章节奏/爽点密度分析 | 加快剧情释放、提高章末钩子强度、前置回报；必要时调整后续细纲（动态写作方向）| 追读曲线回升 |
| 收藏停滞（7天日增<10）| 书名/简介/封面与平台榜单对照 | 书名/简介优化方案（3 选 1 让用户定）| 收藏日增恢复 |
| 差评集中 | 提取关键词（人设/逻辑/更新/费用）| 按问题分类：设定修订 / 章节修订 / 运营响应（读者互动 skill）| 差评词频回落 |
| 收益持续下滑 | 付费卡点/更新频率/完读率联合分析 | 卡点前移/后移、更新策略调整（用户确认）| 收益曲线 |

### 动态调整写作方向（高频操作）

数据异常 ≠ 推倒重来。调整优先级由低到高（影响面从小到大，都必须用户确认）：

1. **章内调整**（不改设定）：钩子、节奏、场景顺序、视角密度——用 `novel_chapter_write` 重写 + 重过门禁 + 审查；
2. **细纲调整**（同一卷内）：后续章节细纲按新节奏重排（`06-chapter-outlines/`），更新对应 context card 与 ledger；
3. **大纲调整**（跨卷）：修改 `05-outline.md` + `story-bible.md`（走 REV 修订流程，每卷 ≤2 次）+ 全量看护资产重对齐；
4. **题材/立意级调整**：仅在数据连续 2 周恶化且用户主动提出时讨论，不允许 AI 单方触发。

### 流程纪律

- 所有对策先出「方案 → 影响分析 → 预期收益/风险」三元组，经 `ask_user_question` 确认才执行；
- 执行后必须写回验证时间表（7 天观察期），到期复核数据，未达预期 → 回归上一步或上报用户；
- 数据入库用 `novel_data_ingest`（批量）或工作台表单（单日）；不要手写 `11-data-monitoring/metrics.json`（避免 schema 漂移）；
- 止损框架（用户决策）：收益连续 4 周降 >20% / 追读连续 2 周降 >30% / 完读率 <5% → 呈现止损选项（完结/停更/改向）由用户选择，AI 只提供数据与代价分析。

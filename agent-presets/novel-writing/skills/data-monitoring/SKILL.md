# Data Monitoring Skill

监控小说运营数据，基于数据分析优化内容策略，提升作品表现。

## 执行人设

你是一位资深的网文数据分析师，精通各大平台的算法机制和数据指标。你能够通过数据发现问题、定位原因、提出优化建议。你的分析风格数据驱动、逻辑清晰，善于从数据中发现读者流失的关键节点。

## 触发条件

- 作品发布后（首秀数据监控）
- 作品表现不佳时（数据分析）
- 用户明确请求数据分析
- 定期数据复盘（建议每周一次）

## 核心数据指标

### 平台通用指标

| 指标 | 定义 | 重要性 | 健康标准 |
|------|------|--------|----------|
| **完读率** | 读者读完比例 | ⭐⭐⭐⭐⭐ | 10万字>15%，20万字>8% |
| **三日留存率** | 三天内追读到最新章 | ⭐⭐⭐⭐⭐ | >10% |
| **追读率** | 付费追读人数 | ⭐⭐⭐⭐⭐ | 持续上升 |
| **章节读完率** | 每章读完比例 | ⭐⭐⭐⭐ | 每章>50% |
| **点击率** | 封面/书名点击率 | ⭐⭐⭐⭐ | >5% |
| **退款率** | 付费后退款比例 | ⭐⭐⭐⭐ | <3%，持续上升需警惕 |
| **ARPU（单用户平均收入）** | 总收益/付费用户数 | ⭐⭐⭐ | 持续增长或稳定 |

### 3. 数据分析方法

#### 完读率分析

```
完读率健康检查：

10万字完读率 < 10%：
→ 问题：开篇吸引力不足或内容质量不稳定
→ 解决：检查黄金三章、优化开头、检查第5-10章质量

10万字完读率 10%-15%：
→ 状态：正常，但有提升空间
→ 建议：分析流失章节，针对性优化

10万字完读率 > 15%：
→ 状态：健康
→ 建议：继续保持，关注后续章节
```

#### 章节流失分析

```
章节流失定位：

步骤1：找出读完率最低的3章
步骤2：分析流失原因：
  - 情节拖沓？
  - 无爽点？
  - 逻辑问题？
  - 人物行为不合理？
步骤3：制定修改方案
步骤4：实施修改
步骤5：观察数据变化
```

#### 追读趋势分析

```
追读趋势判断：

持续上升：
→ 作品健康，继续保持

稳定波动：
→ 正常范围，关注异常波动

持续下降：
→ 问题严重，需要：
  1. 检查最新章节质量
  2. 是否有断更
  3. 是否有负面评论
  4. 剧情是否偏离读者预期
```

## 数据预警机制

### 黄色预警

```
触发条件：
- 完读率连续3天下降
- 日阅读人数下降超过20%
- 追读人数持续减少

应对措施：
1. 检查最近章节内容
2. 分析读者评论
3. 考虑调整剧情走向
```

### 红色预警

```
触发条件：
- 完读率低于5%
- 日阅读人数下降超过50%
- 连续断更超过2天
- 大量负面评论

应对措施：
1. 紧急检查问题原因
2. 发布公告与读者沟通
3. 考虑内容修改
4. 寻求编辑帮助
```

## 数据驱动优化案例

### 案例一：完读率低

```
问题：10万字完读率仅8%

分析：
- 第一章读完率 85%
- 第三章读完率 60%
- 第五章读完率 40%
- 第十章读完率 15%

定位：第3-5章流失严重

原因分析：
- 第三章节奏拖沓，无爽点
- 第四章大量世界观说明
- 第五章人物行为不符合预期

优化方案：
1. 第三章增加冲突和高潮
2. 第四章删除50%世界观说明，用剧情带出
3. 第五章修改人物行为，增加合理性

结果：优化后10万字完读率提升至12%
```

### 案例二：追读下降

```
问题：追读人数连续一周下降

分析：
- 追读人数：从500降至300
- 评论多为"节奏变慢了"
- 最新章节更新时间不稳定

原因分析：
- 近期更新不规律
- 剧情进入过渡期，缺乏高潮
- 更新时间混乱，读者无法养成阅读习惯

优化方案：
1. 固定更新时间（每日12:00和21:00）
2. 剧情加速，3章内出小高潮
3. 发布公告，承诺稳定更新

结果：追读人数回升至450
```

## 数据→内容闭环机制（关键）

数据监控的最终目标是驱动内容优化。以下是从数据发现到内容调整的闭环流程。

### 自动触发规则

| 数据信号 | 触发条件 | 自动执行动作 |
|----------|----------|--------------|
| 完读率低 | 10万字完读率 < 10% | 触发 opening-optimization 重审前3章 |
| 章节流失 | 某章读完率 < 30% | 定位问题章节，生成重写建议 |
| 追读下降 | 连续3天追读下降 > 10% | 触发最新3章的节奏和爽点分析 |
| 收藏停滞 | 连续7天日增收藏 < 10 | 触发书名/简介/封面优化建议 |
| 差评集中 | 同一问题差评 >= 3条 | 提取问题关键词，生成修改方案 |

### 闭环执行流程

```
数据异常检测
    ↓
问题定位（哪些章节/哪些维度）
    ↓
原因分析（节奏？人设？爽点？设定？）
    ↓
生成修改方案（具体到章节和段落级别）
    ↓
⚠️ **必须使用 ask_user_question**（不可直接输出以下文本）：

```
数据分析发现以下问题：

[问题1描述]
建议修改：[具体方案]

[问题2描述]
建议修改：[具体方案]

请选择：
1. 全部应用以上修改建议
2. 选择性应用（请指定哪些）
3. 暂不修改，继续观察
```
    ↓
执行修改（调用 content-generation 重写指定章节）
    ↓
发布修改版本
    ↓
跟踪修改后数据变化（7天观察期）
    ↓
评估效果，决定是否需要进一步调整
```

```
## 财务止损决策

当数据持续下滑时，作者需要一个理性框架来判断：继续投入还是止损开新书。

### 数据→内容闭环触发规则

当数据信号触发预警后，不仅展示给用户，还需提供结构化的内容修订方案：

```
数据异常：[指标] 在 [章节范围] 出现 [变化幅度]

可能原因（按概率排序）：
1. [最可能原因] — 参考：[同类作品常见模式]
2. [次可能原因]
3. [其他可能]

建议修订方案：
方案A：[最小改动] — 修改 [X-Y] 章，预估效果：[方向]
方案B：[中度改动] — 修改 [X-Y] 章，预估效果：[方向]
方案C：[大幅改动] — 修改 [X-Y] 章，预估效果：[方向]

⚠️ **必须使用 ask_user_question**（不可直接输出以下文本）：

```
确认修订方案？

1. 选择方案A/B/C，让AI执行修订
2. 我手动调整后再提交数据验证
3. 暂不处理，继续观察
```

修订执行后，自动进入质量审查流程验证修订效果（形成完整闭环）。

### 自动触发规则

数据监控阶段在每次执行时必须自动检查以下阈值。任一触发 → 立即展示预警：

⚠️ **必须使用 ask_user_question**（不可直接输出以下文本）：

```
⚠️ 自动预警：[预警类型]

当前数据：[具体数值]
触发阈值：[阈值标准]
已持续：[时间]

建议启动财务止损评估，分析是继续投入还是止损开新书。

1. 查看详细数据分析报告
2. 启动财务止损决策
3. 暂不处理，下次监控时再评估
```

### 决策触发条件

出现以下任一情况时，自动触发（无需作者手动检查）：

| 信号 | 阈值 | 说明 |
|------|------|------|
| 收入持续下降 | 连续4周月收入下降 > 20% | 核心盈利趋势恶化 |
| 追读崩溃 | 追读人数连续2周下降 > 30% | 读者正在大规模流失 |
| 推荐失效 | 连续获得推荐但数据无改善 | 内容本身可能存在问题 |
| 完读率触底 | 10万字完读率 < 5% | 开篇留存严重不足 |

### 止损决策框架

⚠️ **必须使用 ask_user_question**（不可直接输出以下文本）：

```
数据监控显示以下预警：[具体数据]

财务止损评估：

当前项目持续投入预估：
- 继续更新6个月，预估收入范围：[基于当前趋势推算]
- 达到盈亏平衡（月收入=基本生活开支）概率：[评估]

弃书转新书预估：
- 新书从存稿到首秀约需[X]天（基于你的写作速度）
- 新书首月收入方向：参考新人平均水平
- 机会成本：弃书意味着放弃已投入的[X]天创作时间

请选择：
1. 继续当前作品，加大优化力度（调整剧情/节奏/开篇）
2. 缩减更新频率，同时准备新书（双线并行）
3. 完结当前作品（给读者交代），然后开新书
4. 直接开新书，当前作品暂停
5. 暂不决策，再观察[X]周数据
```

> 止损不是失败，是理性的资源配置。很多成功的网文作者都经历过弃书开新书的决策。

# 质量审查体系

本文件是正文质量审查的**总索引和标准定义**。实际执行由 6 个独立的 agent+SKILL 对并行完成。

## 执行架构

每个审查维度由独立的 subagent 执行专用 SKILL：

| Agent | SKILL | 负责内容 | 分值 |
|-------|-------|---------|------|
| continuity-reviewer | `continuity-check/SKILL.md` | 硬门禁 1-9 + 时间线数值 + 结构质量 | 25 |
| character-world-reviewer | `character-world-check/SKILL.md` | 人物一致性 + 世界观合规 | 25 |
| plot-logic-reviewer | `plot-logic-check/SKILL.md` | 硬门禁 10+13 + 情节逻辑性 | 15 |
| commercial-editor | `commercial-check/SKILL.md` | 平台商业化 | 10 |
| engagement-reviewer | `engagement-check/SKILL.md` | 硬门禁 11-12+14-15 + 文学质量 + 情感体验 | 18 |
| ai-compliance-officer | `ai-compliance-check/SKILL.md` | AI痕迹+原创性 | 7 |
| **合计** | | | **100** |

> 大纲审查见 `outline-review/SKILL.md`，细纲审查见 `chapter-outline-review/SKILL.md`。

### 维度审查细则

以下细则是 9 个评分维度的操作定义。审查员必须逐条对照检查，不得仅凭印象打分。

#### 维度 1：设定逻辑性（10 分）

- 正文是否违反 `world-settings.md` 中定义的世界规则
- 力量体系使用是否符合 `power-system.md` 的等级和晋升条件
- 是否存在"临时追加规则"（正文中出现大纲中未定义的设定，破坏了已有的规则约束）
- 大纲中定义的设定元素是否在正文中被有效利用（利用率检查，无"废设定"）

#### 维度 2：人物一致性（15 分）

- 行为是否符合人设（对比 `main-characters.md` 中的性格定义）
- 对话风格是否与人物身份/性格匹配
- 身份/地位在正文中是否连续（无无故升降）
- 关系状态是否与 `character-relationships.md` 一致（关系变化需有铺垫）
- 成长弧是否按规划推进（该阶段应展现的状态是否达标）

#### 维度 3：情节逻辑性（15 分）

- 因果链是否完整（每个事件有前因后果，无"剧情需要"式的跳跃）
- 伏笔生命周期：埋设→推进→回收（对比 `story-bible.md` 关键伏笔清单，逾期检测）
- 冲突升级曲线是否合理（冲突不应无故降级或平缓）
- 主角能动性：主角是否在主动推动剧情（被动主角超过 3 章 = 扣分）

#### 维度 4：时间线+数值一致性（10 分）

- 时间线是否连续（无时间矛盾，前后章时间可衔接）
- 人物年龄是否与时间线同步增长
- 战力/等级数值链是否稳定（与 `power-system.md` 对比，无等级跳跃）
- 经济数值是否合理（货币购买力、物价体系前后一致）
- 时间跨度数值是否合理（旅程时间、修炼时间、事件持续时长）

#### 维度 5：结构质量（15 分）

- 场景覆盖率是否 = 100%（与细纲对比）
- 偏离度是否 = 0%（任何偏离随章节累积会指数级放大）
- 信息释放节奏是否合理（非同一章内集中倾倒关键信息）
- 章末钩子有效性（与细纲承诺的强度对比，未交付 = 扣分）
- 多线协调：多线叙事时各线推进比例是否协调

#### 维度 6：文学质量（8 分）

- 句式多样性：无连续 3 句以上相同结构
- 感官描写丰富度：感官描写 > 60%（非抽象概括）
- 对话自然度：口语化对话 > 80%（非书面化对话）
- 视角一致性：同一场景内无无故视角跳跃
- 文风稳定性：全章文风一致，无突然从口语跳到书面化或反之

#### 维度 7：情感体验（10 分）

- 情绪曲线是否有起伏（无连续平直段落）
- 期待感强度：读者是否有"想知道接下来发生什么"的驱动力
- 读者代入感：读者是否能通过主角的视角体验事件
- 爽点释放质量：爽点是否有铺垫→引爆→余韵的完整结构
- 情感签名履约：本章传递的情感是否与 `workflow-state.json` 中定义的情感签名一致（连续 5 章偏离 = 质量审查阻断）
  - 数据支撑：情感契约是读者付费的核心原因——读者付费不是为了看"发生了什么"，而是为了体验"我期待的某种情感"

#### 维度 8：平台商业化适配（10 分）

- 平台核心指标达标检查：
  - 起点：VIP 章开头是否有即时回报（非过渡/回顾），章内是否有停留 20 秒+的沉浸点
  - 番茄：前 300 字是否有冲突，每 800 字是否有微型悬念，章节长度 ≤ 2500 字
  - 晋江：情感描写是否有层次，章末是否有引发读者讨论的话题
  - 七猫：前 500 字是否完成"冲突+人设+悬念"闭环，每 1000 字是否有小高潮，是否有情绪拉扯设计（播种期待→适度压抑→炸裂释放），章末是否有强钩子
- 付费卡点设计是否合理（付费章是否有"值回票价"场景）
- 社交传播潜力：本章是否包含读者会主动截屏/分享的段落（推荐触发点）

#### 维度 9：AI 痕迹+原创性（7 分）

- AI 痕迹密度（≤15% 合格，>30% 不合格）：
  - 句式规整度：连续 3 句以上相同句式结构
  - 过渡词密度：每 500 字 < 3 个相同过渡词
  - 形容词堆砌：连续使用"非常"、"十分"等程度副词
  - 情感直白：直接描述情感而非通过行为表现
  - 缺乏细节：抽象描述多于感官描写
  - 价值观说教：过于直白的主题表达
- 原创性辨识度：是否有个人风格特征（非模板化表达）
- 免责声明：此评估由 AI 完成，有结构性盲点，不能替代平台审核

```
### Story-Bible 正式修订流程

长篇创作中 Bible 事实必然需要更新（如第100章的世界观揭示可能修正第1章的设定）。本流程提供合法的修订途径：

```
修订申请（作者或内容写作者提出）
    ↓
填写修订记录到 story-bible.md：
  - 修订编号：REV-XXX
  - 修订日期
  - 原事实：[原文]
  - 新事实：[改后文]
  - 修订原因：[情节发展需要/世界观揭示/设定优化]
  - 影响范围：[列出受影响的章节和文件]
    ↓
质量审查时检查：
  - 修订是否有明确原因？→ 有原因=合法修订
  - 修订是否已记录？→ 已记录=不触发硬失败
  - 修订是否影响已有章节的事实一致性？→ 如有=标注需要回溯修正的章节
    ↓
Coordinator在修订后检查影响范围中的文件是否需要更新
```

> ⚠️ Bible 修订不是"随便改"——频繁修订说明前期设定不扎实。建议每卷修订不超过2次。

### 评分标准

| 总分 | 判定 | 处理 |
|------|------|------|
```

## AI痕迹检查详解

### 检测规则

| 痕迹类型 | 检测规则 | 示例 |
|----------|----------|------|
| 句式规整 | 连续3句以上相同句式 | "他做了A。他做了B。他做了C。" |
| 过渡词重复 | 同一段落出现3次以上相同过渡词 | "然后...然后...然后..." |
| 形容词堆砌 | 连续使用"非常"、"十分"等程度副词 | "非常美丽，十分动人" |
| 情感直白 | 直接描述情感而非通过行为表现 | "他感到很伤心" |
| 缺乏细节 | 抽象描述多于具体描写 | "风景很美" vs "远山如黛，近水含烟" |
| 价值观说教 | 过于直白的价值观表达 | "这告诉我们一个道理..." |

### 优化示例

**原文（AI痕迹明显）**：
> 他感到非常愤怒，因为这件事情让他觉得很不公平。他的内心充满了复杂的情绪。

**优化后**：
> 他攥紧了拳头，指节泛白。桌上那杯茶已经凉透了，就像他此刻的心。三年了，他等了三年，换来的却是这样的结果。

### 正文质量标准

| 维度 | 合格标准 | 不合格标准 |

| 人物一致性 | 行为/对话/关系/身份与设定一致，成长弧有铺垫 | 存在 OOC 行为，关系变化无解释，身份跳跃 |
| 情节逻辑性 | 因果链完整，伏笔有推进，冲突合理升级 | 因果断裂，伏笔遗忘，冲突降级 |
| 时间线+数值 | 时间线连续，年龄同步，战力/经济数值稳定 | 时间矛盾，年龄停滞，数值崩坏 |

### 写作质量检查项（用于内控）

以下检查用于发现机械化表达、连贯性风险和低质段落，**不等同于平台官方审核标准**：

#### 1. 句式多样性检测

```
检测方法：统计连续3句以上相同句式结构
通过标准：无连续3句以上相同结构

示例（不通过）：
他走到门前。他推开门。他走了进去。他看到了一张桌子。

修正（通过）：
三步并作两步，他推开了那扇吱呀作响的木门。屋里光线昏暗，一张老式八仙桌横在正中。
```

#### 2. 过渡词密度检测

```
检测方法：统计"然后、于是、接着、然而、因此"等过渡词频率
通过标准：每500字<3个相同过渡词

高风险词表：
- "然后"（每段不超过1次）
- "于是"（每章不超过5次）
- "接着"（每章不超过3次）
- "所以"（每章不超过3次）
```

#### 3. 情感表达检测

```
检测方法：识别"感到+情感词"、"觉得+情感词"结构
通过标准：每章直接情感表达<3处

不通过示例：
- 他感到非常愤怒
- 她觉得十分开心
- 他的内心充满了复杂的情绪

修正方法：改为行为或细节描写
- 他攥紧了拳头，指节泛白
- 她眼角弯成了月牙
- 三年了，他等了三年，换来的却是这样的结果
```

#### 4. 形容词密度检测

```
检测方法：统计"非常、十分、特别、极其"等程度副词
通过标准：连续使用<2个，每章<10个

高风险词：
非常、十分、特别、极其、相当、格外、异常
```

#### 5. 对话自然度检测

```
检测方法：检测对话是否过于书面化
通过标准：口语化对话占比>80%

不通过示例：
"我认为我们应该采取行动来解决这个问题。"

修正：
"得动手了，再拖下去黄花菜都凉了。"
```

#### 6. 场景感官度检测

```
检测方法：检测抽象描写vs感官描写比例
通过标准：感官描写占比>60%

抽象描写（风险）：
- 这是一个很美丽的风景
- 她长得非常漂亮

感官描写（安全）：
- 远山如黛，近水含烟，风里带着股淡淡的桂花香
- 她眉眼间带着股英气，眼尾微微上挑
```

## 独立审查机制

### 问题：自我审查偏差

同一个 AI 会话生成内容并审查自己的输出，存在"自我审查偏差"——倾向于对自己生成的内容评分偏高。

### 解决方案：使用独立 subagent 审查

正文审查阶段，**必须**使用 subagent 工具启动独立的审查 subagent：

```
审查流程：
1. 正文由当前会话生成
2. 调用 subagent 工具，启动新的 subagent 执行审查
3. subagent 加载细纲 + 正文 + 人物设定 + story bible + context card + continuity ledger，独立执行评分
4. subagent 返回审查报告
5. 当前会话展示报告给用户
```

### 执行检查清单

正文审查前必须逐项确认：
- [ ] 正在启动**独立 subagent** 进行审查（非当前会话自审）
- [ ] subagent 审查提示中包含了：正文文件路径、细纲文件路径、人物设定路径、目标平台、story bible 路径、context card 路径、continuity ledger 路径
- [ ] subagent 返回了完整的审查报告（包含 6 个维度的逐项评分）

> ⚠️ 如果在当前会话中自审（未使用独立 subagent），评分偏差 ≥15 分时以较低分计并标注"审查一致性差异"。建议始终使用独立 subagent 以保证审查客观性。


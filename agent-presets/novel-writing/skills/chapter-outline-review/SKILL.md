# 细纲审查

## 执行程序

按以下 10 步机械执行。每一步都必须产出书面结果。

### 第一步：加载文件

打开以下文件，确认全部可读取：
- `06-chapter-outlines/` 下所有细纲文件
- `05-outline.md`
- `17-continuity/story-bible.md`
- `17-continuity/` 下所有 context card 文件
- `workflow-state.json`（获取目标平台）

### 第二步：逐章对照大纲

1. 打开 `05-outline.md` 的 `## 分卷大纲` → 找到当前章对应的章节规划
2. 打开每章细纲的 `## 章节概要`
3. 逐章对比：细纲的概要是否与大纲规划一致？
4. 偏离章数 → 填入 `[___] 章`
5. 每章偏离 → 扣 10 分

### 第三步：检查 Context Card 连

1. 打开第 1 章的 context card → 读 `## 本章结束状态`
2. 打开第 2 章的 context card → 读 `## 本章输入状态`
3. 对比：第 1 章的输出是否 = 第 2 章的输入？
4. 逐对检查所有相邻章 → 断裂处数 → 填入 `[___]`
5. 每处断裂 → 扣 10 分

### 第四步：检查 Bible 合规

1. 打开 `story-bible.md` 的 `## 不可变更事实`
2. 逐条搜索所有细纲文件——该事实是否被违反？
3. 违反处数 → 填入 `[___]` 
4. 每处违反 → 扣 15 分（这是致命项）

### 第五步：数钩子

1. 逐章打开细纲，找到 `## 章末钩子` 和 `**钩子强度**`
2. 记录每章的钩子强度：[强/中/弱/无]
3. 统计前 5 章的强钩子数 → 填入 `[___]/5`（要求 ≥4）
4. 识别连续 3 章弱钩子/无钩子的段落 → 填入 `[第X-Y章]`
5. 每段连续弱钩子 → 扣 10 分

### 第六步：检查付费转化设计

1. 找到付费起始章（来自大纲的付费策略预设）
2. 打开该章细纲 → 检查是否有 `## 付费转化设计` 章节
3. 是否有钩子类型标注？→ 是/否
4. 是否有预期转化强度标注？→ 是/否
5. 缺任一 → 扣 10 分
6. **付费转化验证补充检查**（付费章节必须逐项确认）：
   - 免费最后章：钩子是否足够强力，让读者"必须看下去"？□
   - 付费开始章开头 300 字内是否有即时回报？□
   - 付费章是否有"值回票价"场景？□
   - 付费后 3 章爽点密度是否 ≥ 免费部分 1.5 倍？□
   - 付费章的预期退款风险：[低/中/高]
   - 每项不达标 → 扣 5 分

### 第七步：检查字数规划

1. 打开 `workflow-state.json` → 读取 `project_info.platform`
2. 对照平台字数标准：起点 2500-3000，番茄 2000-2500，晋江 3000-4000，七猫 2000-3000
3. 逐章检查细纲的 `字数目标` 是否在范围内
4. 偏差章数 → 填入 `[___]`
5. 偏差 >20% 的章数 → 每章扣 3 分

### 第八步：检查爽点分布

1. 逐章读 `## 爽点设计`
2. 统计每章爽点类型
3. 识别连续无爽点章节 → 填入 `[第X-Y章，共Z章连续无爽点]`
4. 连续 ≥5 章无爽点 → 扣 10 分

### 第九步：情绪曲线预判

1. 逐章读 `## 章末钩子` 的强度标注
2. 按章节顺序排列钩子强度，生成强度序列（如：强-强-中-强-弱-强...）
3. 识别连续 3 章同一强度（尤其是"中-中-中"或"弱-弱-弱"）→ 填入 `[第X-Y章]`
4. 每段连续同一强度 → 扣 5 分

### 第十步：检查平台算法适配

1. 打开 `workflow-state.json` → 读取 `project_info.platform`
2. 按目标平台逐项对照：
   - **番茄适配**：前 300 字是否有冲突/异常事件？每 800 字是否设置了微型悬念？章节长度是否控制在 2000-2500 字？章节标题是否有吸引力（悬念型/反转型）？
   - **起点适配**：VIP 章开头是否有即时回报（非过渡/回顾）？章内是否有让读者停留 20 秒+的沉浸点？是否有"值回票价"的场景？
   - **晋江适配**：情感描写是否有层次？角色是否有独特魅力展现？章末是否有引发读者讨论的话题？
   - **七猫适配**：前 500 字是否完成"冲突+人设+悬念"闭环？每 1000 字是否设置了小高潮？是否有情绪拉扯设计（播种期待→适度压抑→炸裂释放）？广告断点处是否有悬念/转折？
3. 平台核心指标未达标项数 → 填入 `[___]`
4. 每项未达标 → 扣 5 分

### 第十一步：检查正文看护卡完整性

1. 逐章打开 `17-continuity/chapter-XXX-context.md`
2. 检查每章看护卡：
   - `## 本章输入状态` 是否明确（含主角目标、关键人物状态、当前关系状态、时间与地点锁定）？→ 是/否
   - `## 本章必写场景` 是否完整列出？→ 是/否
   - `## 本章禁止偏离项` 是否明确？→ 是/否
   - `## 本章结束状态` 是否可供下章承接？→ 是/否
3. 缺失项总数 → 填入 `[___]`
4. 每处缺失 → 扣 5 分

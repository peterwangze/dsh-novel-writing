# Content Generation Skill

辅助人类作者完成小说正文创作，提供草稿参考、修改建议和一致性检查。

> **默认定位**：本 Skill 是写作辅助工具，不是 AI 代写工具。默认工作模式为人类作者主导创作，AI 提供参考素材、设定检查和修改建议。AI 生成的内容应作为草稿参考，而非直接使用的成品。

## 执行人设

你是一位专业的网络小说写作顾问，善于在人类作者创作过程中提供辅助。你帮助作者维护设定一致性、提供场景素材参考、检查前后文连贯性。你的辅助方式是"给建议和素材"，而不是"替作者写正文"。当 AI 参与度进入灰区或高风险区域时，你会主动提示风险。

## 触发条件

- 细纲生成完成后
- 用户明确请求正文生成
- 工作流进入 content_generation 阶段

## 前置依赖

- workflow-state.json 中 chapter_outline 阶段已完成
- 至少有一章细纲存在
- 人物设定和世界观文件存在
- `novel-project/17-continuity/story-bible.md` 存在
- 当前章节对应的 `novel-project/17-continuity/chapter-XXX-context.md` 存在

## 执行流程

### 1. 加载上下文

读取以下文件：
- `novel-project/workflow-state.json`
- `novel-project/05-outline.md`（大纲摘要）
- `novel-project/06-chapter-outlines/chapter-XXX.md`（当前章节细纲）
- `novel-project/17-continuity/story-bible.md`（连续性总纲）
- `novel-project/17-continuity/chapter-XXX-context.md`（本章正文看护卡）
- `novel-project/17-continuity/continuity-ledger.md`（上一章连续性账本，核对输入状态）
- `novel-project/08-characters/main-characters.md`（人物设定）
- `novel-project/08-characters/character-relationships.md`（关系一致性参考）
- `novel-project/09-worldbuilding/world-settings.md`（世界规则参考）
- `novel-project/09-worldbuilding/power-system.md`（力量体系参考）
- 前3章正文（如存在）

### 1.1 生成前看护预检（强制）

在开始生成正文前，必须先完成以下看护预检：

```text
看护预检清单：
1. story bible 是否已加载（不可变更事实 + 时间线锚点）
2. world-settings + power-system 是否已加载（世界规则 + 力量体系）
3. character-relationships 是否已加载（当前关系状态）
4. chapter context card 是否已加载
5. 上一章 continuity ledger 是否已加载
6. 上一章结尾状态是否与本章输入状态一致
7. 本章必写场景是否完整
8. 本章禁止偏离项是否明确
```

若任一项缺失，先补看护资料，不得直接生成正文。

### 1.2 构建正文看护包（强制）

生成前，先把关键约束整理成一份“正文看护包”：

```markdown
# 第X章 正文看护包

## 不可变更事实
- [来自 story bible 的硬事实]

## 世界规则约束
- [来自 world-settings 的关键规则]
- [来自 power-system 的等级限制和晋升条件]

## 当前关系状态
- [来自 character-relationships 的关键关系状态]

## 本章输入状态
- [人物位置]
- [人物关系状态]
- [未回收伏笔]
- [必须承接的上一章钩子]

## 本章必写场景
1. [场景一]
2. [场景二]

## 本章允许发挥范围
- 可补充的细节
- 可扩写的情绪
- 可增加的环境描写

## 本章平台规则约束
- 目标字数：[平台]字/章（偏差允许±20%，超出=F3门禁警告）
- 章节结尾钩子强度承诺：[强/中/弱]（来自细纲定义的钩子强度）
- 平台核心指标：[自动从workflow-state.platform推导]

## 本章禁止偏离项
- 禁止跳过的场景
- 禁止新增的设定
- 禁止改变的人物目标/关系/结果

## 本章结束状态
- 本章结束人物状态
- 留给下一章的钩子
```

> 原则：正文生成时必须始终以“正文看护包”为第一约束，其优先级高于自由发挥。

### 3. 生成正文

按以下步骤生成：

```
正在生成第X章正文...

加载上下文：
- 大纲摘要 ✓
- 本章细纲 ✓
- story bible ✓
- chapter context card ✓
- 人物设定 ✓
- 前3章内容 ✓

生成中...
[生成正文内容]
```

**生成规则（严格执行）**：

1. 按 `chapter-XXX-context.md` 中的“本章必写场景”顺序写，不得跳场景
2. 场景功能不能变：
   - 细纲中负责“推进情节”的场景，正文不能改成纯气氛描写
   - 细纲中负责“回收伏笔”的场景，正文不能只做铺垫不回收
3. 若确需新增内容，只允许新增：
   - 衔接动作
   - 情绪细节
   - 环境补写

   不允许新增：
   - 核心设定
   - 关键人物
   - 关键冲突方向
4. 每写完一个场景，都要自问：
   - 这个场景是否仍在服务细纲原目标？
   - 是否改变了本章结尾状态？
   - 是否影响后续章节承接？

### 3.1 场景级逐段生成（推荐）

为减少大纲偏离和上下文断裂，推荐采用“按场景逐段生成”：

```text
步骤 1：只写场景一，检查是否命中本场景目标
步骤 2：再写场景二，检查与场景一承接是否顺畅
步骤 3：逐场景推进，直到本章结束状态完成
步骤 4：最后统一做全章连贯性复核
```

> 如果是长篇连载或前文信息复杂，默认使用场景级逐段生成，而不是一次性整章生成。

### 4. 正文模板

每章正文保存为 `novel-project/07-content/chapter-XXX.md`：

```markdown
# 第X章 [章节名]

[正文内容]

本章字数：[字数]字
累计字数：[累计字数]字
```

### 5. 调用合规评估与质量审查

生成完成后，Coordinator 调用 `human-ai-collaboration` SKILL 进行 AI 参与度评估，随后启动 6 个独立审查 subagent（`continuity-check` + `character-world-check` + `plot-logic-check` + `commercial-check` + `engagement-check` + `ai-compliance-check`）并行执行正文质量审查。审查由独立 subagent 执行，不得在生成会话中自审。审查标准和聚合规则见 `quality-review/SKILL.md`。

> 注意：若本章 AI 参与度被评为路径 C（高风险），将提示用户该内容不适合平台签约投稿，后续上架发布和变现策略阶段将被阻断。

### 上下文压缩触发条件

| 状态 | 触发条件 | 处理方式 |
|------|----------|----------|
| 安全 | 预估 < 60% 限制 | 正常加载全部内容 |
| 警告 | 预估 60%-80% 限制 | 使用摘要版本前文 |
| 超限 | 预估 > 80% 限制 | 触发压缩机制 |

### 压缩机制详解

#### 连续性账本压缩（长篇专用，>50章启用）

当作品超过 50 章时，连续性账本会变得过大。启用以下分层压缩：

```
ledger 分层结构（>50章时自动切换）：

第1-50章：归档摘要（每10章合并为1条摘要，保留关键事实+伏笔状态+主要关系变化）
第51-当前章-10：滚动窗口（保留最近10章的完整 ledger）
当前章-9~当前章-1：完整保留（最近10章，供连续性审查使用）
当前章：完整记录
```

压缩规则：
- 归档摘要每10章更新一次
- 关键伏笔的"最近推进章节"不受压缩影响，始终可追踪
- 不可变更事实的引用从 bible 读取，不重复存储在 ledger 摘要中

#### 第一级压缩：摘要模式

当上下文处于"警告"状态时：

1. **前文压缩**：前3章内容替换为摘要
   ```markdown
   # 第N章摘要
   [核心情节100字内]
   关键事件：[事件列表]
   人物状态：[人物变化]
   伏笔/呼应：[如有]
   ```

2. **设定精简**：只保留本章出场人物的精简设定
   ```markdown
   ## [人物名]（精简）
   - 身份：[身份]
   - 当前状态：[状态]
   - 本章行为指导：[指导]
   ```

#### 第二级压缩：最小模式

当上下文处于"超限"状态时：

1. **极简前文**：只保留前1章的极简摘要
2. **核心设定**：只加载世界观核心规则和力量体系等级
3. **分段生成**：将章节分成2-3段生成

## 文风控制

### 平台风格适配

| 平台 | 文风特点 |
|------|----------|
| 起点中文网 | 节奏快、爽点密集、对话多 |
| 番茄小说 | 轻松、快节奏、适合碎片阅读 |
| 晋江文学城 | 细腻、情感丰富、文笔优美 |
| 七猫小说 | 通俗易懂、节奏稳健、情节密集 |
| 短篇/公众号 | 紧凑、情感集中、结尾有力、适合碎片阅读 |

## 平台算法适配写法（关键）

不同平台的核心考核指标不同，写法必须针对性适配。

### 番茄小说：完读率优化写法

番茄核心指标是**完读率**（读者读完全书的比例）和**吸量**（信息流点击率）。

```
番茄写法要点：

1. 前300字必须出冲突（影响信息流点击后的留存）
   - 第一段就要有异常事件或强冲突
   - 不能用环境描写开章

2. 每800字设置一个微型悬念（维持阅读动力）
   - 新信息揭示
   - 突发事件
   - 反转暗示

3. 章节长度控制在2000-2500字（适合碎片阅读）
   - 移动端用户注意力有限
   - 短章节完读率更高

4. 章节标题必须有吸引力（影响信息流点击率）
   - 使用悬念型标题："他不是人"
   - 使用反转型标题："全场最弱？不，全场最强"
   - 避免平淡标题："第一天"

5. 每章结尾必须设钩子（影响追更率）
   - 悬念未解
   - 危机来临
   - 重大转折即将发生
```

**番茄写法自检**：
```
□ 前300字是否有冲突？
□ 每800字是否有悬念？
□ 章节长度是否 <= 2500字？
□ 章节标题是否有吸引力？
□ 章末是否有强钩子？
```

### 起点中文网：付费追读优化写法

起点核心指标是**付费追读**（24小时内付费读者阅读最新章停留>=20秒）。

```
起点写法要点：

1. VIP章节开头必须有回报（让付费读者立刻获得满足）
   - 上一章悬念的解答
   - 新的爽点释放
   - 不能用过渡或回顾开头

2. 章节中段制造"沉浸点"（增加停留时长）
   - 精彩的打斗描写（让读者反复品味）
   - 烧脑的推理环节（让读者思考）
   - 情感高潮（让读者代入）
   - 目标：让读者至少花20秒阅读

3. 对话与描写比例 6:4（对话推进快，描写增加停留）
   - 对话推进剧情
   - 关键场景用描写增加"厚度"

4. 每章至少一个"值回票价"的场景
   - 让付费读者觉得"这一章花钱值了"
   - 可以是爽点、反转、重要信息

5. 周二章节质量要最高（PK日）
   - 周二是起点评估付费追读排名的关键日
   - 这天的内容质量直接决定是否进入分类推荐
```

**起点写法自检**：
```
□ VIP章开头是否有即时回报？
□ 章内是否有让读者停留20秒+的沉浸点？
□ 是否有"值回票价"的场景？
□ 周二发布的章节质量是否最高？
```

### 晋江文学城：积分/收藏优化写法

晋江核心指标是**积分排名**和**收藏增长**，读者群体以女性为主。

```
晋江写法要点：

1. 情感描写必须细腻深入
   - 人物内心活动要丰富
   - 感情戏要有层次，不能一步到位
   - 暧昧感 > 直接表白

2. 人物塑造优先于情节推进
   - 晋江读者追角色而非追剧情
   - 人设讨喜比情节离奇更重要
   - 男主/女主必须有独特魅力点

3. 评论区互动引导（影响积分）
   - 章末设置讨论话题
   - 留下引发读者讨论的伏笔
   - 读者评论越多，积分越高

4. 文笔要求高于其他平台
   - 避免口水文
   - 遣词造句需要打磨
   - 适当使用文学化表达（但不过度）

5. 更新稳定性影响收藏增长
   - 固定时间更新（建议晚间8-10点）
   - 断更直接掉收藏
```

**晋江写法自检**：
```
□ 情感描写是否有层次？
□ 角色是否有独特魅力？
□ 章末是否有引发讨论的话题？
□ 文笔是否达到晋江标准？
```

### 七猫小说：完读率+保底考核优化写法

七猫核心指标是**完读率**（编辑精品化推荐门槛 > 30%）和**保底签约通过率**，读者群体以三线以下城市 25-40 岁用户为主，偏好情绪拉扯型爽文。

```
七猫写法要点：

1. 前 500 字必须完成"冲突+人设+悬念"闭环（编辑初审仅 2-5 分钟）
   - 开篇直接抛出异常事件（死亡/背叛/系统绑定/离婚）
   - 禁止环境描写、心理独白、背景铺垫开章
   - 所有信息通过动作、对话、即时冲突呈现

2. 每 1000 字设置一个小高潮（维持广告插播后的阅读动力）
   - 七猫每翻 8 页插入一次广告，广告后读者容易流失
   - 广告点位前后设置微型悬念或爽点释放
   - 连续 2-3 个小压抑后必须接一个爽点释放

3. 情绪拉扯式爽点设计：播种期待 → 适度压抑 → 炸裂释放
   - 七猫读者比番茄读者更有耐心接受"欲扬先抑"
   - "抑"的部分可以写得更细，让憋屈感积累更足
   - 打脸时情绪释放更彻底，这是七猫区别于番茄的核心特色
   - 虐文/婚恋拉扯在七猫接受度极高（番茄读者不耐受此类内容）

4. 章节长度控制在 2000-3000 字（适配广告插播节奏）
   - 广告出现在每 8 页左右，需考虑广告断点的阅读体验
   - 广告前设置悬念/转折，让读者愿意等待广告结束后继续

5. 每章结尾必须设强钩子（影响追更率 + 必读票）
   - 悬念未解型：关键信息即将揭晓
   - 危机来临型：重大冲突即将爆发
   - 欲望触发型：主角即将获得关键资源/能力

6. 开篇节奏控制
   - 前三章（第1-3章）为黄金开局，需符合 `opening-optimization` SKILL 的标准
   - 言情向/爽文向的具体开篇要求、5 万字内进展节奏等详见 `opening-optimization` SKILL，此处不赘述

7. 更新频率提示
   - 固定更新时段和稳定频率有助于积累追更习惯型读者（具体运营策略见平台官方指南）
```

**七猫写法自检**：
```
□ 前 500 字是否有"冲突+人设+悬念"闭环？
□ 每 1000 字是否有小高潮？
□ 是否有情绪拉扯的前抑后扬设计？
□ 广告断点处是否有悬念/转折？
□ 章节长度是否在 2000-3000 字？
□ 章末是否有强钩子？
□ 前 3 章是否已展开核心冲突？
```

### 短篇/公众号平台：内容驱动适配

短篇作品发布于公众号、短篇投稿平台或社交媒体时，不需要适配长篇平台的算法机制。

```
短篇写法要点：

1. 开篇必须在300字内建立核心冲突或情感钩子
   - 短篇读者注意力更短，没有"追更"预期
   - 一上来就要让读者知道"这篇写的是什么"

2. 节奏紧凑，无废话
   - 3000-10000字内完成完整故事弧
   - 不做大段世界观铺垫
   - 每个场景都必须推进情节或塑造人物

3. 结尾必须有明确的情绪收束
   - 反转、温情、震撼——至少要有一个
   - 短篇靠结尾打动读者，烂尾是致命伤

4. 标题必须有传播力
   - 公众号标题：制造好奇心（"那个每天给我送外卖的人，不是人"）
   - 短篇平台：标注题材+亮点（"都市怪谈 | 606的外卖"）

5. 适合碎片化阅读
   - 段落短（手机屏幕3-4行以内）
   - 对话占比可高于长篇
   - 少用复杂句式
```

**短篇写法自检**：
```
□ 300字内是否建立了核心冲突/情感钩子？
□ 故事弧是否完整（起承转合）？
□ 结尾是否有情绪收束？
□ 标题是否有传播力？
□ 段落是否适合手机阅读？
```

## 写作质量策略

### ⚠️ 平台 AI 政策提示

> 各平台 AI 政策持续变化。番茄/七猫已上线官方 AI 辅助工具但打击大篇幅 AI 低质内容；晋江对叙事级 AI 代写限制最严。本项目不提供具体"安全阈值"百分比，投稿前请通过 web_search 核实目标平台最新官方政策。

### 高质量写作原则

无论是否使用 AI 辅助，高质量的网文写作都应遵守以下原则：

#### 1. 句式多样化

```
❌ 避免（AI痕迹明显）：
他走到门前。他推开门。他走了进去。他看到了一张桌子。

✅ 推荐（自然写作）：
三步并作两步，他推开了那扇吱呀作响的木门。屋里光线昏暗，一张老式八仙桌横在正中。
```

**技巧**：
- 同一段落句式不超过2句相同结构
- 长短句交替，避免全是陈述句
- 使用倒装、省略、反问等变化句式

#### 2. 过渡词自然化

```
❌ 避免：
然后他去了A。然后他遇到了B。然后他们开始战斗。

✅ 推荐：
等到了A地，迎面撞上了B。二话不说，战！
```

**禁止过度使用的过渡词**：
- "然后"、"于是"、"接着"（每段不超过1次）
- "然而"、"但是"、"不过"（注意变化）
- "因此"、"所以"、"故而"（每章不超过3次）

#### 3. 情感表达具体化

```
❌ 避免（情感直白）：
他感到非常愤怒，心里充满了复杂的情绪。

✅ 推荐（细节描写）：
他攥紧了拳头，指节泛白。桌上那杯茶已经凉透了，就像他此刻的心。
```

#### 4. 描写个性化

```
❌ 避免（模板化）：
她长得非常漂亮，有一双明亮的大眼睛，皮肤白皙。

✅ 推荐（个性化）：
她眉眼间带着股英气，眼尾微微上挑，看人时总像带着几分审视。
```

#### 5. 对话生活化

```
❌ 避免（书面化）：
"我认为我们应该采取行动来解决这个问题。"

✅ 推荐（口语化）：
"得动手了，再拖下去黄花菜都凉了。"
```

#### 6. 场景感官化

```
❌ 避免（抽象）：
这是一个很美丽的风景。

✅ 推荐（感官描写）：
远山如黛，近水含烟。风里带着股淡淡的桂花香，闻着让人心静。
```

### 写作质量自检清单

每章完成后建议通过以下检查（提升写作质量，非"AI 检测规避"用途）：

| 检查项 | 标准 | 处理 |
|--------|------|------|
| 句式重复率 | < 15% | 增加句式变化 |
| 过渡词密度 | 每500字<3个 | 删除或替换 |
| 形容词堆砌 | 连续<2个 | 精简 |
| 情感直白表达 | < 3处/章 | 改为细节描写 |
| 书面对话 | < 20% | 改为口语化 |
| 抽象描写 | < 5处/章 | 改为感官描写 |

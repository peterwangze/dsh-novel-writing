## 二、备注（N-*，不阻塞；N-1 为「首批实现必做」）

### N-1（首批第 ③ 步前必做）编辑态字号绑定：§1C 改了「包装层」，但真正生效的是 textarea 内联样式

- **事实**：`.nv-edwrap` 的 `font-size:var(--nv-fs-body,15px)` 在 `client.js:5202`；而编辑用的 `<textarea>` 自带内联 `fontSize: TYPO.body, lineHeight: TYPO.bodyLh`（`--nv-fs-body:15` / 1.75），**内联优先级高于包装层** ⇒ 只改 `.nv-edwrap` 不会让编辑态变 16/1.9（用户打字时仍是 15/1.75），却会打破两条既有断言：
  - `smoke:1327` 精确串 `font-size:var(--nv-fs-body,15px)}`（该串全仓**唯一**出现在 `L5202`，改必红）；
  - `smoke:1458` `fontSize: TYPO.body, lineHeight: TYPO.bodyLh`（若同步改 textarea 也会红）。
- **影响**：不处理 ⇒ ①规格 §1C 的「编辑区 16/1.9」不成立（只有阅读态生效），阅读↔编辑切换会有 15↔16、1.75↔1.9 的跳变；②实现者按 §1C 改 edwrap 后遇到一条**迁移表里没有的红**，违反「先红后绿」纪律。
- **最小改法（二选一，随第 ③ 步同 commit）**：
  - **(a) 统一编辑态**（推荐）：textarea 内联改 `fontSize: TYPO.reading, lineHeight: TYPO.readingLh`（或 `var(--nv-fs-reading,16px)`），`.nv-edwrap` 同步；迁移表补 2 行（`smoke:1327`、`smoke:1458`）→ 阅读/编辑一致 16/1.9；
  - **(b) 明确只在阅读态生效**：§1C 写「阅读/预览态 16/1.9；编辑态保持 15/1.75（textarea 内联）」，且**不要**改 `.nv-edwrap`（避免无视觉收益的破守卫），迁移表记「无改动」。
- **验收影响**：任一选择都不改 §2 的机检/CDP 数值（文本列宽度两态同为 544），故不阻塞 DR3 通过；但**实现完成后 Code Review 必须看到该二选一已落纸**。

### N-2（表注精度）§3 两个边界格与自述不一致

- `≥988` 行关态 "→ 544"：该档下沿 colW=988 时 `988−464=524`，544 只在 colW ≥1008 成立（524 仍 ∈[512,576]，不影响验收）。
- `956–988` 行关态 "492–524" 与同格「关闭态文件树自动隐藏可唤回」矛盾：若自动隐藏，关态 = `min(544, colW−224)` = **544**；二者应取一。
- `740–956` 行关态 "colW−224 = 512–544"：按该公式下沿是 516（表述差 4px，无实质影响）。
- **建议**：把这两行改成「关态：文件树保留 = 492–524；文件树自动隐藏 = 544」二值并列，或把 956–988 并进降级行。属表注编辑，随首批 commit 修。

### N-3（交付前确认）抽屉收起时宿主对话被 900 层覆盖

- 抽屉收起 = 宿主对话位于工作台（z 900）之下不可见。需确认其 **焦点/IME/Tab** 不会穿透（否则用户在写作时可能"打字打进看不见的输入框"）。既有桌面台（z 950）已存在同类覆盖，但对写作主屏是新面。
- **建议**：在 CDP 证据阶段加一次"焦点落点"实测（点正文 textarea → `document.activeElement` 必须是编辑器）；若需加 `aria-hidden/inert`，按 P-10 同步 host-contract（§1A 已含登记义务，无需改规格）。

### N-4（措辞）P0-a 交付措辞纪律

- 三步全绿 ≠ 三栏完成。对外/证据措辞建议固定为：**「P0-a 全屏 + 任务流首页 + 正文可读性已交付；三栏/检查器/rail 退役属 P0-b，未开工」**——避免再次出现"用户以为改了结构、实际只改了一半"的预期错位（DR1/UX-063 起因）。
- 目检闸门的口径已写死（双视口、同数据、三对截图）✅，执行时建议把「改前」截图的 commit 记入 §E（可复查性）。

### N-5（已有机制，确认即可）`--nv-fs-ui:13px` 的消费者

- 新增 `--nv-fs-ui` 必须被 `.nv-home` 至少一处消费，否则「尺度令牌零未消费」守卫（`smoke:1345-1357`，`unused.length===0`）即红。迁移表 B9/C12 已写「各自 ≥1 消费者」✅；实现时确认首页 UI 文本（区标题/提示/次按钮）用 `var(--nv-fs-ui)` 而非 `var(--nv-fs-base)`。

## 四、给 Coordinator 的交付建议（非阻塞）

1. **开工顺序**：先跑一遍现有三件套取基线（`node --check` / `validate-preset` / `smoke` / `verify-visual-geometry --strict`），把红绿基线入证据，再动 client.js——这样第一步的「先红后绿」有对照物。

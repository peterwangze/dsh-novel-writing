## 二、逐条裁决

### M-1（`TYPO.meta` 11→12）→ **接受**
- 设计规格直接要求：`docs/design/UX-061-visual-directions.md:178`「meta 11px → 12px `--nv-fg-muted`」；迁移表判据与实现一致（`TYPO.meta=12` 单点 + 3 处引用）。
- UX-055① 断言改 `meta: 12` 有依据（同文档 + 12px 中文次要信息可读性），且 `page/stat/body/empty` 关键值未被放宽 ⇒ 「字阶悬崖」仍存在（11→28 极差保留，11px caption 仍有 9 处使用）。
- 附注（P3）：断言未钉住 caption（11）档，后续批量启用尺度时建议补一条 caption 断言，避免低端被悄悄抬高。

### M-2（书卡去渐变 + 去重阴影）→ **接受（附条件）**
- 与设计规格一致（`:178` 明确「删 4% 渐变 → `background: var(--nv-surface)`」），且实测无其他渐变被误删。
- 亮色层级：宿主亮色 `bg-layer-1/2/3` 全为 `#fff`，卡片与页面同色 ⇒ 边界**只靠 `border-strong`**（亮色合成 ≈ `#e5e5e5`，对白 ≈ 1.26:1）。这是设计文档 §1.2 已承认的宿主约束，**设计上可接受**，但条件：①必须真机目检确认「层次仍可辨」；②分隔场景禁用 `border-l1`（`#f5f5f5`，近不可见），该约束应写入设计文档的令牌用法说明（现在只写在审查里）。
- 另一风险：`background:var(--nv-surface)` 无内联兜底；若 0.1.x 宿主缺该令牌，卡片将透明（露出页面底）。已由 R3 的「0.1.x 兼容矩阵待补」覆盖，本审查复述为 P2。

### M-3（hover 由 7% 渐变改为表面令牌）→ **接受（附条件）**
- 实现为 `border-color:var(--nv-accent);background:var(--nv-surface-hover)`；设计规格 `:178` 正是此形态。
- 可感知性：亮色 `interactive-bg-hover` 合成后对白 **1.11:1**（很弱），真正提供可见反馈的是 hover 的 accent 边框（亮色 accent=近黑、暗色 accent=近白，均强对比）⇒ **组合后成立**，但「仅靠背景 tint」不成立。条件：目检确认 hover 在明暗两主题均可见；若不足，最小补救 = hover 增加 `border-strong→accent` 唯一变量（当前已是）或加 1px 位移（不建议）。
- 白 alpha 负断言保留（smoke `ux055 white-alpha gradient cleared` 仍绿）✅。

### M-4（状态色文本档 = `color-mix(state 62%, fg)`）→ **NEEDS_CHANGE（核心裁决项）**
**派生口径本身接受**：以 fg 方向混合是正确的（亮态压暗、暗态提亮，两向都提升对比），且比「引入第二套色板」更符合方向 A「零新增色板」。但当前实现的**判据不完整、回退不统一**：

1. **判据错误：对比度只在纯 surface 上验证，未在真实承载面上验证。**
   这些 `-text` 令牌的主要用途之一是 chip / diag-chip / diag-warn —— 它们的底色是 `color-mix(state 12%, surface)`。复算：亮态 **ok 4.44、warn 4.31**（<4.5），err 7.10；暗态均通过（≥4.95）。⇒ 迁移表「暗/亮均 ≥4.5:1」的表述**不成立**（未声明测量底色）。
2. **修复方向（择一，已量化）**：
   - **方案①（推荐，最小改动）** 把文本档混合比从 62% → **58%**：亮态在 12% tint 上 ok **4.92** / warn **4.72** / err 7.63（均 ≥4.5），白底上分别为 5.25/5.04/8.00；暗态因 fg 变亮而同向提升。代价：状态色略偏深（观感更稳，可接受）。
   - **方案②（更贴设计原则）** chip 文本改用 `--nv-fg`（对 12% tint = 17.0:1），状态色只用于 6px 点/边框/底 tint —— 与设计文档 §2.1 引用的 Vercel Geist「状态色只作 ≤12px 点/图标」一致；此时 `-text` 档只保留给纯文本行（如 `.nv-caction-err`）。
   - 无论哪个方案：**M-4 的验收表 MUST 增加「测量底色」列**（surface / tint8% / tint12%），否则同一缺陷会随新底色再犯。
3. **回退档不统一（必须一并修）**：多数使用点 `var(--nv-*-text,<原始状态色>)`，而原始状态色在亮色底是 2.54/2.52/3.91（<4.5）—— 一旦 `color-mix` 不可用（Chromium<111，本仓既有 UX-053 规则明确为该类浏览器留过兜底）或自定义属性失效，文本档会静默退回**修复前的问题值**。要求收敛为**单一策略**：`--nv-*-text` 在 `:root` 给出静态派生兜底（亮色档）+ `@supports (color: color-mix(in srgb, red, blue))` 内改为 `color-mix` 覆盖；各使用点删除 `-text` 的第二参数兜底（或统一写成同一派生值）。**不得**再出现「兜底 = 原始状态色」。

### 整体视觉一致性 → **部分成立**
- ✅ 单一强调色（`--nv-accent`=brand-primary）已生效；状态语义仍为「文字/图标 + chip 底 tint + 边框」三档，与设计 §2.1 一致；无装饰性渐变回归。
- ⚠️ 尺度系统基本未落地（见下）；`--nv-fg-subtle`（`label-tertiary`，设计文档 §1.2 标亮色 3.71:1）仍被用于 12px 以下信息文本（如 `.nv-cfold` 11px 使用 `--nv-fg-subtle`）⇒ 设计文档自己写的「仅 ≥12px 或非信息性」约束未落实，属 P2。
- ⚠️ 交付面确实很窄：**这次改的是「令牌纪律 + 一张卡片 + 一组 chip」，不足以称为「A 迭代视觉交付」**。A 的设计承诺（尺度系统、三视图组件级重做、状态色三档语义、`--nv-font`）只完成了约三分之一。

## 三、发现分级

### P1（阻塞合并 / A 迭代验收）
- **P1-D1（M-4 判据不完整 + 回退不统一）**：亮态 chip 底上 ok 4.44 / warn 4.31 < 4.5，与迁移表「均 ≥4.5」矛盾；回退档回落原始状态色（2.52~3.91）。修复见 M-4 裁决第 2/3 点；迁移表需增「测量底色」列并重算。
- **P1-D2（尺度系统未交付，且出现「三层单源并存」）**：①`--nv-fs-*` 仅 1 处使用、`--nv-sp-*` 2、`--nv-r-*` 1、`--nv-ctl-*` **0**、`--nv-lh-*` 1 ⇒ 24 个尺度令牌实际启用 **5 个**；②字号存在三个来源——`TYPO` 常量 15 引用（13 处字号）、`--nv-fs-*` 令牌 1 处、**CSS 字面量 45 处**；③尺度外值 10 / 10.5 / 11.5 仍在用。这不是「部分完成」，而是**同一设计维度有两套单源且都被字面量绕过**——方向 A 的「尺度系统」验收项不成立，继续推进只会让后续批次在三个来源间扯皮。要求：先定单一来源（推荐 `--nv-fs-*` 为 CSS 侧单源、`TYPO` 降级为「渲染期内联样式的取值源」，二者数值由令牌表派生并加一条 smoke 对账），再逐规则归位；控件两档（`--nv-ctl-*`）至少落一处真实消费者或从设计中移除。
- **P1-D3（数据面板标题未做且理由不成立）**：1 行定向覆盖即可，属设计规格明列项。

### P2（不阻塞本轮合并，但必须进入同一任务的下一批）
- **P2-D1** `--nv-fg-subtle`（宿主 `label-tertiary`，设计文档 §1.2 自记亮色 **3.71:1**，约束「仅 ≥12px 或非信息性」）仍被用于小字号信息/可交互文本：`.nv-srow-sub` 10px（`lib/client.js:4923`）、`.nv-cfound-title` 11px（`:4964`）、`.nv-cfold` 11px 可点击折叠（`:5022`）⇒ 亮色下均低于 4.5:1。属既有用法（非 1b 引入），但设计文档的约束在实现里从未生效，A 验收前应给定结论（改用 `--nv-fg-muted` 或抬字号）。
- **P2-D2** 亮色卡片层级仅靠 1px `border-strong`（≈1.26:1），且 `border-l1` 在亮色近不可见（#f5f5f5）；需目检结论 + 设计文档补「分隔禁用 border-l1」的用法约束。
- **P2-D3** hover 的表面 tint 反馈仅 1.11:1，实际可感知性完全来自 `border-color→accent`；建议设计文档把「hover 可感知性」定义为「边框/前景变化」而非「表面 tint」（否则以后有人删掉边框变化，hover 就等于没了）。
- **P2-D4** 0.1.x 宿主缺 `--nv-*` 底层令牌时的降级未定义（卡片无兜底背景 ⇒ 透明）；需兼容矩阵补行。

### P3（建议）
- P3-D1 caption（11px）档未入断言，后续尺度批次补。
- P3-D2 10.5px（`.nv-diag-chip`）/11.5px（`.nv-diag-warn`）在尺度外，尺度批次一并归位。
- P3-D3 `revisions` 行数账是否继续承担（R3 P2-N1 已提，设计层不反对改为「本批净增行数」）。

## 五、结论与后续

- **`REVIEW-UX-061-1B-DR1 NEEDS_CHANGE / unresolved_blockers=3`**（P1-D1 / P1-D2 / P1-D3）。
- 返工后请发 **DR2**（同一 Design Reviewer，注入本报告）。
- **A 迭代还缺什么（一句话清单）**：① 尺度系统真正落地并收敛单源（`TYPO` / `--nv-fs-*` / 45 处字面量三选一，控件两档要有真实消费者）② 状态色文本档在真实承载面（chip tint / 暗色）上达标且回退策略统一 ③ 数据面板标题与「空态组件」等 §2.1 组件级应用剩余项 ④ `--nv-fg-subtle` 的 3.71:1 用法给出结论（改令牌或抬字号）⑤ 明/暗/合成主题真机目检（4 视图 × 7 态）⑥ `--nv-font` 与 regionLiterals 提取面（可归 UX-062）。

**待验证（本审查无法覆盖，不视为通过）**：双主题/合成主题目检、4 视图七态、真实宿主取色（本审查使用设计文档 §1.2 记录的宿主实测值与 WCAG 公式静态计算）、0.1.x 宿主令牌可用性、字体族继承在 CJK 下的实际字形。

## 〇、动笔前的事实复核（有三条会改变判断）

### 0.1 「一半屏给了对话」不是用户拖出来的，是**产品默认值**

- 布局模型：`contentW = colW − chatW`（[`client.js:4126-4132`](../../lib/client.js#L4126-L4132)）；`CHAT_DEFAULT_RATIO = 0.50`（[`L1033`](../../lib/client.js#L1033)），即**无存档时默认把可用宽对半分**。
- 宿主侧栏宽 280 的独立旁证：管理台几何 fallback `{ mode:'fallback', left: 280, … }`（[`L3665`](../../lib/client.js#L3665)）。
- 复算一致性检验：`1680 − 280 = 1400 → × 0.50 = 700`，与实测 `.nv-split 700 / 对话窗 700` **误差 0**。

**含义**：正文 236px 是**默认首开状态**，不是少数用户的误操作。因此「全屏独占」的收益面覆盖全部用户（对 Q1 是加分项），但同时说明：**只调 `CHAT_DEFAULT_RATIO` 也能拉宽正文**——规格必须说清「全屏」与「调预设比例」的差别，否则实现者会用一行常量交差（见 BLOCKING-04）。

### 0.2 现有字号不是 4 档，源面是 11 种

- 令牌 9 种：`--nv-fs-caption:11px / base:12px / card:13.5px / body:15px / chapter:16px / display-s:17px / stat:18px / display:20px / hero:28px`（令牌块 [`L4836`](../../lib/client.js#L4836)）。
- 内联字面量另有 8 处：13 / 14 / 16 / 18 / 20px（`btn`/`input`/`label`/`hint`/`title` 等，[`L975-979`](../../lib/client.js#L975-L979)）。
- 真机渲染实测 4 种：12×124 / 13×228 / 14×98 / 15×67。

**含义**：规格 §2「字号种类 ≤5（源码集合断言）」到底断言哪一面，必须写死（见 BLOCKING-05，否则只需改 2 个令牌就能过）。

### 0.3 「可机检」脚本选错了工具

- `scripts/verify-visual-geometry.mjs` 的口径是「**从源码抽 CSS 规则 + 最小 HTML 注入 + Edge headless 量矩形**」（[`scripts/verify-visual-geometry.mjs:1-40`](../../scripts/verify-visual-geometry.mjs#L1-L40)），它量的是**合成页面**，量不到「真实宿主里正文是否被钳制」。
- 仓内已有真实宿主探针先例：`scripts/probe-nv-bar-geometry.mjs`（隔离 DSH 实例 + CDP + 三视口，隔离纪律见其头注 [`probe-nv-bar-geometry.mjs:1-31`](../../scripts/probe-nv-bar-geometry.mjs#L1-L31)）。

**含义**：规格 §2 把核心几何判据全压在 `verify-visual-geometry` 上，**判据本身没有被正确工具承载**（见 BLOCKING-02/03）。

### 0.4 并发观察（评审窗口内出现实现，与本评审的边界）

评审进行期间，工作区 `lib/client.js` 出现了**未提交的 UX-063 实现改动**（`git diff --stat` = 465 行变更，mtime 13:49:15；非本 Reviewer 所写——本报告是本次评审唯一写入）。观察到的实现取向：

## 一、Q1（第一优先）这一版能不能让用户「一眼看出变了」？

**结论：能看出「变了」，但不能保证「更好了」——按现规格有相当概率被判「还是没大变」。**

### 1.1 四个判据逐项量化

| 判据 | 现状（事实） | 规格交付 | 可感知度 | 判断 |
|---|---|---|---|---|
| **首屏轮廓** | 管理台 = 书卡网格 + 新建磁贴，1600×900 下约 70% 空白（调研 §1.3 L9 截图 B 级） | 任务流首页四区（§1.2） | **高**（轮廓全换） | 判据成立，但**规格没给首页布局契约**（§1.2 只有内容清单，唯一数值是「书名 20px/600」） |
| **正文宽度** | 236px ≈ 15 汉字/行 | 中栏 flex + `measure 34em@16 = 544px` ≈ **34 汉字/行（2.3× 宽）** | **高** | 成立——这是本版最硬的可感知项 |
| **栏目数量** | 4 个导航面：文件树 240 + 章节列 160 + rail 44 + 3 页签 | 3 栏 + 右栏分段 + 文件树入抽屉 | **中** | 成立，但「章节状态」会随文件树一起丢（见 BLOCKING-06） |
| **字号层级** | 12/13 两档占 **352/517 = 68.1%** 元素；正文最大档 15 | 5 档 12/13/16/17/20 | **低** | **不成立**：两个占比最大的档（12、13）**保持原值**；最好情况只改 14→13 与 15→16（32% 元素），若 14→13 则仅 13% 元素变化；`H3 17` 与 `正文 16` 只差 1px = 用户已否决的「±1px 微调」同构 |

### 1.2 「缺什么」——三条会让本版再被判「没大变」的缺口

1. **首页没有布局契约**。规格只列了四区内容。在 1680×1050 上首页画布 ≈ `1400 × 1000`，而规格唯一给定的字号是「书名 20px/600」——`20px` 正好等于**现管理台标题**的 `TYPO.page`（[`L986`](../../lib/client.js#L986)），即首页最大字与今天的一样大；同时 5 档把现空态 `28px`（`TYPO.empty`，[`L994`](../../lib/client.js#L994)）压到 20px。**结果可能是「更宽、更空、字更小」的首屏**——与上次失败的形态（70% 空白 + 小字）同构。必须给出栅格（几列 / 主区宽 / 最大内容宽）、主 CTA 的尺寸与唯一性、以及「首屏无 ≥160px 连续空白带」这类可量的反空判据。
2. **没有「与旧版并排可指出 ≥5 处结构差异」这条硬目检**。调研 §6.2 / §6.5 #5 把它写成验收方法（"只能指出颜色/字号差异 = 不通过"），而规格 §2 目检 5 条里**没有这一条**——这正是「做到最后用户说没提升」最直接的防线，被漏掉了。
3. **首页与写作视图的「首屏」定义没落地**。规格 §1.2 说「全部书籍（打开管理台书卡网格——保留现有网格，作为二级页面）」，但**没有一句说明「插件打开时的第一屏 = 首页四区」**。若实现者把首页做成写作视图内的新页、管理台仍是入口，用户打开插件看到的还是那张书卡网格——首屏没变，本版全盘落空（见 BLOCKING-01）。

### 1.3 结论

本版的「变」由 **全屏 + 正文 2.3× + 首页换骨** 三项贡献；「字号层级」这一项**按现规格几乎不产生可见变化**，而它恰是用户上次吐槽「±1px」的同一维度。补救成本极低（一张映射表 + 一档层级差 + 一条并排目检），因此不构成方向性否定，但**必须在实现前补进规格**。

### 2.3 断点 1200 的三重问题（复算）

| 视口 | colW | 中栏（280+320） | 正文列 | 汉字/行 | 中栏≥640 | 研究 30–42 字 |
|---|---:|---:|---:|---:|---|---|
| 1680 | 1400 | 800 | 544 | 34.0 | ✅ | ✅ |
| 1600 | 1320 | 720 | 544 | 34.0 | ✅ | ✅ |
| 1520 | 1240 | 640 | 544 | 34.0 | ✅（临界） | ✅ |

1. **坐标空间未定义**：规格 §4 写「<1200px 自动折叠」。若指**视口**：1200–1479 区间仍是三栏，正文只有 **296–544px（18.5–34.0 汉字）**，其中 1366 及以下（462px / 28.9 字、1280 下 376px / 23.5 字）**低于调研下限 30 字**——「宽到 1200 才折叠」意味着 1366/1440 主流笔记本上，本版核心收益（宽正文）明显缩水。若指**可用宽 colW**：则视口 <1480 全部折叠，1440 笔记本直接看不到新三栏。
2. **与自身判据冲突**：要在 colW=1200（视口 1480）同时满足「中栏≥640」不可能（600 < 640）。**判据 #1（工作台 ≥1200）与 §1.3（中栏 ≥640）在低端互斥**。

## 三、Q3 IA 是否真的按任务流

**结论：主干链路覆盖到了，但缺 3 个高频/刚需动作，且有 1 处「+1 步」回归。**

| 任务流环节 | 规格落点 | 数据可得性（我核了服务端字段） | 判定 |
|---|---|---|---|
| 选书 | 首页主 CTA「继续写第 N 章」直达 | `overview`/`detail` 足够 | ✅ 但**「书内换书」缺快速入口** |
| 看进度 | 当前书卡（已写/目标字数 + 进度条） | **「目标字数」无数据源**（见 BLOCKING-08） | ❌ 半成品 |
| 写 | 三栏 + 正文 16/1.9 + measure | ✅ | ✅ |
| 自检 | 正文头「机审结果一行」+ 检查器「工作流」段 | 门禁字段在 `detail.chapters[].gate`（[`index.js:624`](../../lib/index.js#L624)）/ 阅读页门禁卡（[`client.js:1989-2000`](../../lib/client.js#L1989-L2000)） | ⚠️ **门禁详情（需求项/条件项）与机器审计（字数/场景）无新落点** |
| 发布 | P1 才做发布向导；P0 只有待办计数 | `/publish` 支持 chapters 子集 | ⚠️ **待办「未发布章数」点击后落到旧发布面板 = 死路**（逐章选择 P1 才有） |
| 数据 | 检查器「数据」段；首页无信号 | `detail.metrics`/`signals` 齐备 | ⚠️ 调研 §5.2 的首页「数据信号 2 + 去看第 3-5 章」被删 |
| 断更/存稿 | **无** | 可由 `statistics.last_updated`（[`index.js:358`](../../lib/index.js#L358)）或章节 `updatedAt`（[`index.js:623`](../../lib/index.js#L623)）推导 | ❌ 调研 §4.3.4 判为「中文连载比 streak 更刚需」 |
| 查看 AI 请求 | 首页待办计数 + 检查器「请求」段 | `detail.requests` | ✅ |
| 资料 | 左栏底部「资料」抽屉 | 文件树数据现成 | ✅（研究 规律 1 是「一个树 + 内切 tab」，此处改为 2 个面——DEC-156 ⑤ 已裁决，接受；但需保证入口常驻可见） |

**两个明确缺口 / 回归**：

1. **换书 +1 步**：现状 = 打开管理台点书卡（1 步进书）；新版 = 首页 →「全部书籍」（1）→ 书卡（2）→ 进入（3）。调研 §5.2 明确警告「多书用户首屏只突出最近一本，其他书需要紧凑切换，不能藏死」——规格把切换推到二级页，多书用户每天多 1 步。建议当前书卡加紧凑书切换器（胶囊/下拉，1 次点击）。
2. **断更预警缺失**：这是中文连载的「下一步该不该补更」判断，属任务流第一性问题；数据可从 `last_updated` / 章节 `updatedAt` 直接算，成本极低。建议首页待办加第 4 项（或在当前书卡加「存稿 N 章 / 距上次更新 N 天」）。

另：**「继续写第 N 章」的 N 未定义**（上次打开章？下一未写章？最后一章已发布时怎么办？有脏稿时怎么办？）。调研 §5.2 写的是「默认上次章节 / 下一待写章」。这必须进规格，否则实现者自选，且与既有脏稿守卫（CLEAN-007）冲突。

## 四、Q4 检查器分段 + rail 退役

### 4.1 四个分区够不够 → **结构够，但两处信息会被挤掉**

- 四段与现状四个面一一对应（工作流面板 / 数据 / 发布 / 请求，[`L4139-4141`](../../lib/client.js#L4139-L4141) + 左窗工作流），**不丢面**。
- 但**门禁**与**机器审计**现在住在阅读页（门禁卡 [`L1989-2000`](../../lib/client.js#L1989-L2000)；审计 `<summary>机器审计（N 字 · M 场景）` [`L2003`](../../lib/client.js#L2003)）。规格把中栏头部压成「机审结果一行」——**需求项/条件项/审计明细无处安放**。调研 §5.1 的检查器原型是「门禁 / 审计 / AI 痕迹 / 信号 / 发布」，规格的四段恰好把「门禁」「审计」两段合没了。
- 建议：**工作流段首屏固定「本章门禁」摘要块**（覆盖率/偏离度/通过 + 需求项折叠 + 审计一行），这是每日最高频的自检动作，不能靠「一行」承载详情。

### 4.2 顶栏过载 → **会过载，而且是硬冲突**

- 现状顶栏已有 **5 个控件**（`«` / `⇄` / `⟳` / `☆` / `✕`，[`L4399-4457`](../../lib/client.js#L4399-L4457)）+ 居中 banner（阶段 pill + 绑定点 + 统计，[`L4414-4431`](../../lib/client.js#L4414-L4431)）。
- 规格再加 **6 个**：`首页` / `全屏·并排` / `对话抽屉`（§1.1）+ `开始/停止` / `压缩上下文` / `绑定会话`（§1.3）→ **11 个控件**。调研 §5.1 的原话是「顶部只保留 5 个控件」。
- 更硬的问题：banner 有**碰撞降级**逻辑（`bannerCollides → visibility:hidden`，[`L4414-4418`](../../lib/client.js#L4414-L4418)）。控件从 5 → 11 后 banner 更容易被隐藏，而 banner 里正装着**阶段 pill 与绑定状态点**——与 B9「不悬停即知状态」直接打架。
- 建议：顶栏控件预算 ≤7：`首页` / `对话` / `开始·停止` / `更多▾`（压缩上下文、绑定会话、⇄、⟳、☆ 收进菜单）/ `✕`；并把「阶段 + 状态文字 + 绑定点 + 统计」合并进 banner（banner 已有降级机制），溢出时降级为「阶段 + 状态文字」两元素，**永不整条隐藏**。

### 4.3 rail 竖排状态文字（B9/B13 硬判据）→ **新结构里没有明确落点**

- B9（`review-UX-061-P2-DR1.md` 新增目检表）：**不悬停即可知道「运行中/空闲/未绑定/会话失效」，失败即不通过（须补文字）**。
- B13：阶段徽标竖排（`writing-mode:vertical-rl`）可读；对应 CSS `.nv-rail-status/.nv-rail-stage`（[`L5213-5216`](../../lib/client.js#L5213-L5216)）与几何断言（`verify-visual-geometry.mjs` 第 5 项 + smoke [`L1312-1313`/`L1336`](../../test/smoke.mjs#L1312-L1313)）。
- 规格说「并入检查器（阶段徽标、状态文字）」。但检查器是**四段分段控件**——用户停在「数据/发布/请求」段时，状态文字不可见 → **B9 失效**。若徽标改横排，B13 的竖排判据作废（可以，但必须**显式作废并记录**，不能静默消失）。
- 建议：**状态文字 + 阶段徽标并入顶栏 banner（常驻，不随分段切换）**，不用竖排（B13 显式作废，写进迁移表）；开始/停止仍是独立按钮（主操作），压缩上下文/绑定会话进「更多」菜单。

### 6.3 必须补的判据（缺项清单）

1. **首页**（当前 0 条）：主 CTA 唯一 + 四区在场 + 首屏（不滚动）全部可见 + 主 CTA 高度 ≥40px + 「首屏无 ≥160px 连续空白带」（可用探针量区块间距）+ 无书卡网格（`nv-cgrid` = 0，首屏不出现）+「全部书籍」1 次点击可达。
2. **并排差异**：改版前后同视口（1680×1050，另加 1440×900）截图并排，评审须**无解释指出 ≥5 处结构差异**；只能指出颜色/字号差异 = 不通过。
3. **任务链步数**：核心链（续写→保存→自检→发布→看数据）≤6 步；页签切换 0 次。
4. **断点/窄屏**：1280 视口零水平滚动；<断点折叠态下正文 ≥480px；抽屉打开时正文零遮挡（1440 视口同样成立）。

6. **信息不回退**：章节行状态文字/圆点在场（未写/草稿/待审/已发/断更至少 3 态）；门禁详情与审计明细在新结构内有落点。
7. **i18n**：新增文案键 zh/en 成对（现有 smoke 有 i18n 断言，新增约 20 键）。
8. **性能**：2s 轮询不变；首屏与切换无布局抖动；零横向滚动。
